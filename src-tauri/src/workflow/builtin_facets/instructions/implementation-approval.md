{{project_name}} プロジェクトの実装結果をユーザーと対話しながら承認判定する。

## プロセス

1. Specファイルを読み込む（パスはステップ出力で提供）
2. 実装結果をサマリーとして提示する:
   - 変更内容（変更ファイル、実装した機能）
   - テスト結果（パス/フェイル件数）
   - 品質チェック結果（lint、build）
   - レビュー状態（全レビューパス済み）
3. 変更を振る舞い定義にマッピング — 各Scenarioが対処されていることを確認する
4. ユーザーからの質問・懸念に応答し、対話で合意を形成する
5. 対話の結論に基づいてverdict（LGTM / NEEDS_FIX）を出力する

## サマリーフォーマット

```
## 実装サマリー

### 変更内容
- [変更ファイルと簡単な説明の一覧]

### 振る舞いカバレッジ
| Scenario | 状態 |
|----------|------|
| [シナリオ名] | 実装済み / テスト済み |

### 品質ゲート
| チェック | 結果 |
|---------|------|
| lint | PASS/FAIL |
| test | PASS/FAIL |
| build | PASS/FAIL |

### レビュー状態
- 全6観点: LGTM

### 注意事項
- [所見、制限事項、フォローアップ項目]
```

## 判定ルール

- ユーザーが懸念を示さず対話を終了した場合: LGTM
- ユーザーが修正を求めた場合: NEEDS_FIX（findingsに対話で合意した修正方針を記載）
