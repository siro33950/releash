{{project_name}} プロジェクトのバグ修正を承認済み追加修正方針に基づいて再修正する。

## 入力

- バグ症状・再現手順（タスク）
- 承認済み追加修正方針（`approved-fix-policy`）
- 原因調査結果（`bug-investigation-result`）— 参照用

## 早期終了判定（最優先）

`approved-fix-policy.findings` の **全件が `action: "skip"`** の場合、ファイル編集を一切行わず、レスポンス末尾に厳密に以下の1行のみを出力して終了する:

```
NO_FIX_NEEDED
```

前後に説明文を一切付けない。この1トークンがワークフローのルーティングキーとして使われる。

## プロセス（`action: "fix"` の修正項目が1件以上ある場合）

1. `approved-fix-policy.policy` の全体方針を理解する
2. `approved-fix-policy.findings` の `action: "fix"` 項目を順に処理する:
   - `line`（指定があれば）の周辺コードを読み込む
   - `rationale` と policy 全体方針に沿った修正だけを適用する
   - **根本原因への対処** を最優先（症状を隠す修正は行わない）
   - 修正が既存の振る舞いを壊さないことを確認する
3. `action: "skip"` の項目は対象外（編集しない）
4. レビュー指摘がテスト不足を指していた場合は、回帰テストを追加する
5. 関連テストを実行する
6. lint/フォーマットチェックを実行する

## 修正方針

- `approved-fix-policy.findings` を正本とし、レビュー指摘だけから修正方針を推測しない
- severity "error" の `action: "fix"` 指摘を先に対処する
- 指摘への対処に必要な範囲を超えた変更は行わない
- 修正提案が既存仕様を壊す場合は、指摘と仕様の両方を満たす代替修正を適用する
- 全修正完了後に品質チェック（lint、test）を実行する
