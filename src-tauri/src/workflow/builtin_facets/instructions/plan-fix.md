{{project_name}} プロジェクトのSpecファイルをレビュー指摘に基づいて修正する。

## 入力

前のレビューステップからのレビュー指摘（ステップ出力経由）を受け取る。各指摘にはseverityと修正内容の説明が含まれる。

## プロセス

1. Specファイルを読み込む（パスはステップ出力で提供）
2. 各レビュー指摘を分析する
3. 各指摘について:
   - Specの修正が必要な箇所を特定する
   - 全体構造を維持しながら修正を適用する
   - 表面的な症状ではなく根本原因に対処する
4. 全ての修正をSpecファイルに反映する

## 修正方針

- severity "error" の指摘は全て対処する（ブロッキング問題）
- severity "warning" の指摘は修正方法が明確な場合に対処する
- 適切な修正が曖昧な指摘には、最も保守的な修正を適用する
- 指摘への対処に必要な範囲を超えた内容追加は行わない
- 既存のSpecのスタイルと用語の一貫性を維持する

## 出力

Specファイル更新後、specファイルパスを構造化出力として出力する。
