{{project_name}} プロジェクトのコードを承認済みバグ修正方針に基づいて修正する。

## 入力

- バグ症状・再現手順（タスク）
- 承認済み修正方針（`approved-fix-policy`）
- 原因調査結果（`bug-investigation-result`）

## 早期終了判定（最優先）

`approved-fix-policy.findings` の **全件が `action: "skip"`** の場合、ファイル編集を一切行わず、レスポンス末尾に厳密に以下の1行のみを出力して終了する:

```
NO_FIX_NEEDED
```

前後に説明文を一切付けない。この1トークンがワークフローのルーティングキーとして使われる。

## プロセス（`action: "fix"` の修正項目が1件以上ある場合）

1. `approved-fix-policy.policy` の全体方針を理解する
2. 入力の根本原因分析を参照し、表面的な症状ではなく **根本原因** に対処する修正を行う
3. `approved-fix-policy.findings` の `action: "fix"` 項目を順に処理する:
   - `line`（指定があれば）の周辺コードを読み込む
   - `rationale` と policy 全体方針に沿った修正だけを適用する
   - 修正が既存の振る舞いを壊さないことを確認する
4. `action: "skip"` の項目は対象外（編集しない）
5. 修正に対応する **回帰テスト** を追加する（バグの再発防止のため、再現条件を捉えたテスト）
6. 関連テストを実行する
7. lint/フォーマットチェックを実行する

## 修正方針

- 根本原因の修正のみ行う（表面的な if 分岐の追加で症状を隠さない）
- `approved-fix-policy.findings` を正本とし、policy にない指摘から修正を推測しない
- severity "error" の `action: "fix"` 指摘を先に対処する
- 必要最小限の変更にとどめる（リファクタリングを兼ねない）
- 全修正完了後に品質チェック（lint、test）を実行する
