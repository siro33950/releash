{{project_name}} プロジェクトのコードをレビュー指摘に基づいて修正する。

## 入力

- コードレビューステップからのレビュー指摘（ステップ出力経由）
- ユーザーがApproveした実装修正方針（`approved-fix-policy`、ステップ出力経由）
- Specファイルパス（ステップ出力経由）— 参照用

## プロセス

1. レビュー指摘を読み込む — 各指摘にはファイル:行、問題の説明、修正提案が含まれる
2. Approve済みの実装修正方針を読み、修正範囲と優先順位の正本として扱う
3. Specファイルを読み込み、要求と振る舞い定義のコンテキストを把握する
4. 各指摘について:
   - 関連コードを読み込む
   - 根本原因を理解する
   - Approve済み方針に沿う修正だけを適用する
   - 修正を適用する
   - 修正が既存の振る舞いを壊さないことを確認する
5. 各修正後に関連テストを実行する
6. lint/フォーマットチェックを実行する

## 修正方針

- `approved-fix-policy` を必ず確認し、レビュー指摘だけから修正方針を推測しない
- severity "error" の指摘を先に対処する
- 次に "warning" の指摘を対処する
- 指摘への対処に必要な範囲を超えた変更は行わない
- 修正提案が振る舞い定義のScenarioに違反する場合は、指摘とScenarioの両方を満たす代替修正を適用する
- 全修正完了後に品質チェック（lint、test）を実行する
