## 前提

Specファイル（ステップ出力で提供）を読み込み、`## 要求` セクションが存在することを確認する。

## Gherkin作成方針

- **Declarativeスタイル**: 実装詳細ではなく振る舞い（何が起きるか）を記述する
- **1シナリオ = 1振る舞い**
- **ビジネス言語**: ドメイン用語を使用する
- **Ruleによる分離（必須）**: 「操作→状態変化」と「状態→表示」は別のRuleブロック・別のシナリオに分離する

## スコープ

ビジネスルールに関わる振る舞いのみ。境界値・技術的エラーはユニット/統合テストの責務。

## Specファイル更新

Specファイルの `## 振る舞い定義` セクションを追加または更新する:

```markdown
## 振る舞い定義

```gherkin
Feature: [機能名]
  Rule: [状態遷移のビジネスルール名]
    Scenario: [シナリオ名]
      Given [前提状態]
      When [操作]
      Then [状態変化]
```
```

## 出力

Specファイル更新後、specファイルパスを構造化出力として出力する。
