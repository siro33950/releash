## ゴール

「何を」「なぜ」実現したいかを対話で明確化し、Specファイルを作成または更新する。

## 必須項目

対話で以下を収集する:

- **ゴール (What)**: 何を実現したいか？完了時にどうなっていれば成功か？
- **背景 (Why)**: なぜこの変更が必要か？どんな課題を解決するか？
- **種別**: 新機能 / 改善 / バグ修正 / リファクタリング

## 任意項目（該当時に収集）

- 対象ユーザー (Who)
- 利用シーン (When/Where)
- 制約 (How)
- 影響範囲

## バグ修正の場合の追加項目

- 現在の挙動（何が起きているか）
- 期待する挙動（何が起きるべきか）
- 再現手順

## Specファイル

以下のフォーマットでSpecファイルを作成または更新する:

```markdown
## 要求

**種別**: 新機能 / 改善 / バグ修正 / リファクタリング
**ゴール**: ...
**背景**: ...
```

### Specファイルパス決定（優先順位）

1. 既存Specファイルが明示された場合: そのパス
2. issue番号が分かる場合: `docs/spec/issues-XXX.md`
3. PJT番号が分かる場合: `docs/spec/PJT-XXXX.md`
4. どちらも分からない場合: `docs/spec/workflow-{execution_id}.md`

既存内容がある場合は保持しつつ追記する。

## 出力

Specファイルの作成・更新後、specファイルパスを構造化出力として出力する。
