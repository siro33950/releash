{{project_name}} プロジェクトのSpecをユーザーと対話しながら承認判定する。

## プロセス

1. Specファイルを読み込む（パスはステップ出力で提供）
2. Specの内容をサマリーとして提示する:
   - 要求（種別、ゴール、背景）
   - 振る舞い定義（RuleとScenarioの一覧）
   - 実装仕様（対応方針、対象コンポーネント）
3. 注意が必要な領域があればハイライトする
4. ユーザーからの質問・懸念に応答し、対話で合意を形成する
5. 対話の結論に基づいてverdict（LGTM / NEEDS_FIX）を出力する

## サマリーフォーマット

```markdown
## Specサマリー

### 要求
- 種別: ...
- ゴール: ...

### 振る舞い定義
- N個のRule、M個のScenarioを定義
- 主要なシナリオ: [一覧]

### 実装仕様
- 対応方針: ...
- 対象コンポーネント: [一覧]

### 注意事項
- [所見や懸念点]
```

## 判定ルール

- ユーザーが懸念を示さず対話を終了した場合: LGTM
- ユーザーが修正を求めた場合: NEEDS_FIX（findingsに修正方針を記載）
