## 要求

**種別**: バグ修正
**現在の挙動**: ファイルの変更を破棄した後、外部（Agent、エディタ等）から同じファイルを再度修正すると、Diffビューに破棄前の古いファイル内容が表示される。破棄時点でファイルリストからは消えるが、再度変更が発生した際にDiffビューの内容が最新のファイル状態を反映しない。
**期待する挙動**: ファイル内容が外部から変更された場合、Diffビューは常に最新のファイル内容で更新される。変更の発生元（Agent、外部エディタ、手動編集等）に関わらず、ファイルシステム上の変更が検知された時点でDiffビューの表示内容が更新されるべき。
**再現手順**:
1. ファイルに変更がある状態でDiffビューを開く
2. Gitから変更を破棄する（ファイルリストから消える）
3. 外部（Agentやエディタ等）から同じファイルを再度修正する
4. Diffビューに破棄前の古い内容が表示される（最新の変更内容ではない）
**背景**: ファイル監視（watcher）からのイベントでDiffビューの内容が適切に再取得・更新されていない可能性がある。変更破棄後にキャッシュされた古い内容が残り、再変更時にそのキャッシュが使われている。

## 振る舞い定義

```gherkin
Feature: Diffビューのファイル内容リアルタイム更新
  ファイルシステム上の変更が検知された際に、Diffビューは常に最新のファイル内容を表示する。

  Rule: ファイル変更検知時にDiff内容が最新化される
    Scenario: 外部からファイルが修正された場合にDiff内容が更新される
      Given ファイルに変更がありDiffビューに表示されている
      When 外部（Agent、エディタ等）からそのファイルが修正される
      Then Diffビューの内容が最新のファイル内容で更新される

    Scenario: 変更破棄後に再修正された場合にDiff内容が最新化される
      Given ファイルに変更がありDiffビューに表示されている
      And Gitから変更を破棄しファイルリストから消えた状態である
      When 外部からそのファイルが再度修正される
      Then Diffビューの内容は再修正後の最新内容で表示される

  Rule: 変更破棄時にDiffの内部状態がクリアされる
    Scenario: 変更を破棄した時点で該当ファイルのキャッシュが無効化される
      Given ファイルに変更がありDiffビューに表示されている
      When Gitから変更を破棄する
      Then 該当ファイルのDiff内容のキャッシュが無効化される
      And ファイルリストから該当ファイルが消える
```

## 実装仕様

**対応方針**: ファイル変更イベント（`file-change`）発火時にも`gitRefreshKey`がインクリメントされるようにし、`useFileDiffContent`のuseEffectが再実行されてDiffビューが最新内容で更新されるようにする。

**根本原因**: `useGitEventRefresh`の`onRefresh`コールバックは`useGitStatus`の`fetchStatus`のみを呼び出しており、`gitRefreshKey`をインクリメントしていない。Stage/Unstage操作後は`refreshAfterAction()`で明示的にインクリメントされるが、外部ファイル変更イベント経由ではインクリメントされないため、`useFileDiffContent`のuseEffectが再実行されずDiff内容が更新されない。

**対象コンポーネント**:
- `src/components/panels/ReviewPanel.tsx`: `useGitEventRefresh`のonRefreshコールバックで`gitRefreshKey`もインクリメントする

**影響するテスト**:
- 単体テスト: `useFileDiffContent.test.ts` — 既存テスト（gitRefreshKey変更時のre-fetch）がカバー済み。ReviewPanel側のイベント連携テストを追加
