## 要求

**種別**: バグ修正
**現在の挙動**: AgentChat画面でスクロール可能になると、縦横両方にブラウザデフォルトのスクロールバーが表示される。横スクロールバーが表示されることで画面幅が変わってしまう。
**期待する挙動**: カスタムスクロールバーUIが適用され、スクロールバーが画面幅に影響を与えない（オーバーレイ表示）。横スクロールは発生しない。
**再現手順**:
1. AgentChat画面を開く
2. メッセージが増えてスクロール可能な状態になる
3. 縦横両方にスクロールバーが表示され、横スクロールバーにより画面幅が変わる
**背景**: チャットUI改善マイルストーンの一環。スクロールバーが画面レイアウトに影響を与え、UXを損なっている。

## 振る舞い定義

```gherkin
Feature: AgentChatメッセージ領域のスクロールバー表示
  AgentChat画面のメッセージ領域でスクロールが必要になった際、
  カスタムスクロールバーが適用され、画面レイアウトに影響を与えない。

  Rule: メッセージ領域は縦方向のみスクロールする
    Scenario: メッセージがビューポートを超えた場合
      Given AgentChat画面が開いている
      When メッセージが増えてメッセージ領域の高さを超える
      Then 縦方向のスクロールが有効になる

    Scenario: コンテンツは領域幅で折り返される
      Given AgentChat画面が開いている
      When メッセージ内容が領域幅を超える長さである
      Then コンテンツは領域幅で折り返して表示される
      And 横方向のスクロールは発生しない

  Rule: スクロールバーは画面レイアウトに影響を与えない
    Scenario: スクロールバー表示時のコンテンツ幅
      Given AgentChat画面が開いている
      When 縦スクロールバーが表示される
      Then スクロールバーはコンテンツ領域に重なって（オーバーレイで）表示される
      And メッセージ領域のコンテンツ幅が変化しない
```

## 実装仕様

**対応方針**: AgentChatメッセージ領域のスクロールを、既存の `ScrollArea` コンポーネント（Radix UI）に置き換え、コンテンツの折り返しを徹底する。

**対象コンポーネント**:
- `src/components/panels/AgentChatPanel/AgentChatPanel.tsx`: メッセージリストの `div (overflow-y-auto)` を `ScrollArea` コンポーネントに置き換え。`scrollRef` と `onScroll` の接続方法をRadix UIのViewport APIに適合させる
- `src/index.css`: `.markdown-preview pre` と `.markdown-preview table` が親コンテナ幅を超えないよう `max-width: 100%` を設定。テーブルには `overflow-x: auto` のラッパーまたは直接スタイルを追加し、テーブル単体でスクロールを閉じ込める

**検討した代替案**:
- CSSのみの修正（`overflow: overlay` 等）: 動作するが、既にプロジェクト全体で `ScrollArea` を使う統一的なパターンがあるため、一貫性のためにコンポーネントを使用する
- `overflow-x: hidden` で横方向を隠す: コンテンツが切れるだけで折り返しにならないため不適切

**リスク**:
- `scrollRef` の参照先がRadix UIの `Viewport` 要素に変わるため、自動スクロール（`scrollIntoView`）の動作確認が必要

**影響するテスト**:
- フロントエンド: AgentChatPanelのテストで `ScrollArea` のモック追加が必要な場合がある
