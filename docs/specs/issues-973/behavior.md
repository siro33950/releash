## Behavior

本 issue は `repository` ドメインのアーキテクチャ移行（純粋リファクタリング）であり、外部から観測可能な振る舞いを変えないことが要件である。したがって観測可能な振る舞いは「移行前後で結果が等価であること」に集約される。

```gherkin
Feature: repository ドメインの Git 操作の振る舞い保持

  Rule: デスクトップ利用者の操作結果は移行前後で等価である
    Scenario: ブランチ・コミット・履歴・ワークツリー・状態・git 設定の操作が同じ結果を返す
      Given デスクトップ利用者が対象リポジトリを開いている
      When 利用者がブランチ・コミット・履歴・ワークツリー・作業ツリー状態・git 設定（releash base 等）のいずれかの操作を行う
      Then 移行前と同じ操作結果が得られる

    Scenario: 操作が成立しない状況は同じ失敗として観測される
      Given デスクトップ利用者が対象リポジトリを開いている
      And 要求した操作が成立しない状況にある
      When 利用者がその操作を行う
      Then 移行前と同じ失敗として観測される

  Rule: リポジトリパス一覧の操作結果と変更通知は移行前後で等価である
    Scenario: リポジトリパスの追加・削除・取得が同じ結果を返す
      Given デスクトップ利用者がリポジトリパス一覧を保持している
      When 利用者がリポジトリパスの追加・削除・取得を行う
      Then 移行前と同じ一覧結果が得られる

    Scenario: リポジトリパス変更時に同じ変更通知が観測される
      Given デスクトップ利用者がリポジトリパス一覧を保持している
      When 利用者がリポジトリパスを変更する
      Then 移行前と同じ変更通知（repo-paths-changed）が観測される

  Rule: リモート利用者の操作結果は移行前後で等価である
    Scenario: リモート経由のブランチ情報取得・ワークツリー一覧/選択が同じ結果を返す
      Given リモート利用者が対象リポジトリへ接続している
      When 利用者がブランチ情報の取得・ワークツリー一覧の取得・ワークツリーの選択のいずれかを行う
      Then 移行前と同じ操作結果が得られる

    Scenario: リモート経由でも操作が成立しない状況は同じ失敗として観測される
      Given リモート利用者が対象リポジトリへ接続している
      And 要求した操作が成立しない状況にある
      When 利用者がその操作を行う
      Then 移行前と同じ失敗として観測される
```
