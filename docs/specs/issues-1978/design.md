- 汎用の配信の口から terminal を除く: `StateSubscriptionOutput` の `start` の引数 `terminal_input_id` と `set_terminal_snapshot`（`usecase/state_subscription.rs:30,54-60`）を除き、terminal の扱いは terminal の配信の口へ移す。根拠: R-001。ルート: 下の「固定するルート」の 4
- presenter の開始の手順を terminal の Usecase へ移す: `present_terminal_start`（`adaptor/presenter/state_subscription.rs:193-243`）の手順を terminal の Usecase へ移す。根拠: R-001。ルート: 下の「固定するルート」の 5
- terminal 用の presenter を分ける: `TerminalSurfaceStateSink` の実装（`adaptor/presenter/state_subscription.rs:419-545`）、失敗の配信の terminal の分岐（`:344-352`）、最初の状態の設定（`:404-416`）、送り待ちの量と通知単位（`:131-143`）を、汎用の `StateSubscriptionPresenter` から terminal 用の presenter へ移す。汎用の presenter は terminal の Usecase を持たない（`:53-68`）。根拠: R-001。ルート: 下の「固定するルート」の 4
- 配信の土台から terminal の経路を除く: `terminal_routes`・`terminal_boot`・`terminal_version`・`register_terminal`・`unregister_terminal`・`terminal_route`（`infrastructure/state_subscription.rs:20-21,29-30,34-94`）を配信の土台から除く。`terminal_boot`・`terminal_version` は terminal 用の presenter へ移し、`terminal_routes` は terminal の出力の中継の登録表へまとめる。根拠: R-001。ルート: 下の「固定するルート」の 9・12
- terminal の登録表を一つにする: terminal の出力の中継の登録表（`adaptor/presenter/terminal_event_hub.rs:21`）だけを持ち、session から対象への対応はそこから導く。terminal の出力を受け取る口 `TerminalSurfaceStateSink`（`usecase/terminal_surface/output.rs:44-49`）の登録・削除・出力の受け取りは、中継が選んだ登録を受け取る形に変える。根拠: R-001（汎用の配信の土台に terminal の経路を持たない）、R-002。ルート: 下の「固定するルート」の 12
- 出力の番号の判断を配信の土台へ移す: 出力の番号を今の版と比べて、最初の状態を取り直させる・捨てる・差分として積む、を決める判断（`adaptor/presenter/state_subscription.rs:518-543`）を、配信の土台の差分で進む対象の操作へ移す。根拠: R-001。ルート: 下の「固定するルート」の 10
- stream の開閉と送り待ちの溢れを controller で受ける: stream を開く・終わる・送り待ちが溢れるきっかけ（`adaptor/presenter/state_subscription.rs:145-171,257-281`）を、controller が受けて汎用と terminal の両方の Usecase を呼ぶ形にする。根拠: R-001。ルート: 下の「固定するルート」の 2

## 固定するルート
1. terminal の購読は、汎用の購読の Usecase の口の実装として作るのではなく、terminal の Usecase の側に置き、controller が対象で振り分ける。usecase が実装する usecase の trait は部品の一覧（`docs/architecture/README.md` の「部品の一覧」）に無いため。振り分けの後も、今と同じ状況で同じ失敗を返す。terminal 以外の対象に入力の識別子が付いたときの失敗、入力の識別子の検査、対象が terminal で入力の識別子が無いときに client の識別子を使うこと（`usecase/state_subscription.rs:118-119`）、terminal の開始が `starts` を取らないことを含む。
2. stream の開閉と送り待ちの溢れ
   - 溢れのきっかけは配信の土台の stream のループが出す（`infrastructure/state_subscription.rs:142-155`）。controller は、これを Usecase の引数に変えて Usecase を呼ぶ（`docs/architecture/CONTROLLER.md` 原則）。presenter は Usecase を持たず、controller から受け口を受け取って、開閉と溢れのときに呼ぶだけにする（`docs/architecture/PRESENTER.md` 原則）。
   - stream を開くときは、controller が汎用と terminal の Usecase に client を開かせ、そのあと配信の土台に開かせる。どこかで失敗したら、それまでに開いたものを閉じる。同じ client の識別子の二重の open は、今と同じ `AlreadyExists` にする。
   - stream が終わるときの順番は今と同じにする。両方の Usecase の後始末を先に行い、そのあと汎用の購読の Usecase の購読中の対象の集合の中で配信の土台を片付ける（`adaptor/presenter/state_subscription.rs:263-281`）。
   - 溢れの受け口は、対象の文字列を対象に変えられなければ何もしない（`:167`）。terminal 以外の対象の溢れでは、terminal の Usecase に何もさせない（`usecase/state_subscription/terminal.rs:75-77`）。
3. 購読中の対象の集合（最初の状態を捨てない対象を決める集合、`adaptor/presenter/state_subscription.rs:283-293`、`usecase/state_subscription.rs:529-545`）は、汎用の購読の Usecase の集合だけから作る。terminal は含めず、集合を Usecase の間で受け渡す仕組みも作らない。この集合は、Usecase に登録してから配信の土台に登録するまでの間に、別の client の停止や切断で最初の状態が捨てられないように守るためのものである（`usecase/state_subscription.rs:533-534`）。丸ごと送る対象では、捨てられると続く開始が失敗する（`infrastructure/state_subscription.rs:407-410`）。差分で進む terminal の対象では、捨てられても最初の状態が無くなるだけで、変化の履歴は消えず（`:784-790`）、対象も消えない（`:758-762`）。最初の状態が無い状態は、出力が届くたびに起きる状態（`:593`）と同じであり、新しい購読者には最初の状態の再要求と作り直しを経て最初の状態が届く（`:407,428,682-688`）。外から見える値は変わらない。
4. terminal 用の presenter: terminal の配信の口と `TerminalSurfaceStateSink` を実装する部品を、汎用の `StateSubscriptionPresenter` から分けて terminal 用の presenter とする。terminal 用の presenter は、汎用の presenter と同じ配信の土台（`StateSubscriptionRuntime`）を共有する。
5. 開始の手順: 次の手順を terminal の Usecase が持つ。terminal の今の世代を読む。その世代の出力の順番の lock に入る。中で世代が変わっていれば抜ける。配信の土台に購読を登録する。最初の状態を待つ側でなければ送り待ちの量を読む。流量制御に購読者を登録する。lock に入れなければ最初からやり直す（`adaptor/presenter/state_subscription.rs:210-241`）。世代の照合とやり直しは中身を変えない。購読の登録と送り待ちの量の読み出しは、terminal の配信の口の 1 つの操作にする。この操作の引数は内側の語彙（対象、`(epoch, sequence)` の cursor）で書き、戻り値は、最初の状態を待つ側なら無し、そうでなければ送り待ちの量とする（`:229-230` と同じ意味）。lock の順番は「出力の順番の lock → 配信の土台の lock」のままにし、逆順で取る経路を作らない。
6. terminal の Usecase は、開いている client と、client ごとの購読中の terminal の対象とその入力の識別子を、1 つの表（client → (対象 → 入力の識別子)）で持つ。開くと空の行を作り、閉じると行ごと消す。開始の順番は今と同じにする。client が開いているか確かめる、入力の識別子を記録する、配信の口で購読を登録する、もう一度確かめる。後の確かめで失敗したら、流量制御の登録と配信の土台の購読を戻す（`usecase/state_subscription/terminal.rs:34-48`）。開いていなければ今と同じ `StreamEnded` で失敗する。切断では、terminal の Usecase が client を閉じてから後始末する。
7. 最初の状態の作り直しのループ（`usecase/state_subscription.rs:500-526`）は、中身を変えずに terminal の Usecase へ移す。作り直しの task は terminal の Usecase が自分の表で持ち、購読が無くなった対象の task は terminal の Usecase が自分の停止で止める。
8. 失敗: 入力の識別子が不正であることと、購読が無いことの失敗（`usecase/state_subscription/reads.rs:29-30`）は、購読の失敗の列挙に残す。terminal の Usecase の購読の操作は、今どおり購読の失敗（`StateReadError`）を返す。この 2 つの失敗を作るのは terminal の Usecase だけにし、汎用の購読の Usecase には作る箇所も分岐も残さない。失敗の種類、転送の番号（`adaptor/presenter/connect.rs:529-530`）、message は今と同じにする。入力の識別子の検査（`usecase/state_subscription/terminal.rs:5,22-27`）は、境界も含めて中身を変えずに terminal の Usecase へ移す。
9. 配信の土台に残すもの: `terminal_boot`・`terminal_version` は terminal 用の presenter が持つ。配信の土台には、差分で進む対象の汎用の操作（`register_delta`・`unregister`・`current_version`・`update`・`mutate` 等）だけを残す。送り待ちの上限は差分で進む対象一般の設定として `register_delta` の引数に残し、値（`OUTPUT_PENDING_LIMIT`）は terminal 用の presenter が渡す。
10. 出力の番号の判断は、配信の土台の差分で進む対象の操作として、版（epoch・sequence）と、版を進める事象かどうかだけで書く。結果は今と同じにする。対象が無ければ何もしない。版を進めない事象で番号が今の版より小さければ、最初の状態を取り直させる。版を進めない事象で番号が今の版と同じなら、その版で積む。版を進める事象で番号が今の版以下なら、捨てる。それ以外は積む（`adaptor/presenter/state_subscription.rs:518-543`）。変更の知らせを出す条件も今と同じにする。配信の土台の操作は結果（積んだ・捨てた・取り直させた・失敗）を返すだけにし、ログは今どおり presenter で出す（`:526,539`）。
11. terminal の購読の停止での配信の土台の片付けは、その terminal の対象だけにする。client のその対象の購読を外し、その対象に購読者がいなくなれば、その対象の最初の状態を捨てる。他の対象には触れない。この操作は配信の土台に汎用の語彙で置き、捨て方は今の `release_inactive_snapshots_except`（`infrastructure/state_subscription.rs:777-795`）と同じにする（差分で進む対象は最初の状態だけを捨て、変化の履歴は残す。`:784-790`）。今の terminal の停止は汎用の停止の経路を通り、購読者のいない全ての対象の最初の状態を、汎用の購読の Usecase の集合で守りながら捨てている（`usecase/state_subscription.rs:133-140`、`adaptor/presenter/state_subscription.rs:117-129`）。terminal の Usecase はこの集合を持たないので、同じ片付けを呼ぶと、開始の途中にある丸ごと送る対象の最初の状態を捨てて、その開始を失敗させうる（`infrastructure/state_subscription.rs:407-410`）。他の対象を片付けていたのは、汎用の停止の経路を共有していたことによる副作用で、terminal の停止の責務ではない。購読者のいない丸ごと送る対象の最初の状態は、次の汎用の停止や切断で捨てられる。terminal の停止は `starts`（`usecase/state_subscription.rs:431`）を取らない。`starts` は丸ごと送る対象の開始と停止を直列にするための lock であり（`:201-202`）、terminal の停止はそれらの対象に触れない。terminal の開始と停止の競合は、固定するルート 6 の client の表の確かめ（開始の前後 2 回）で防ぐ。
12. terminal の登録表は、terminal の出力の中継（`TerminalSurfaceEventHub`、`adaptor/presenter/terminal_event_hub.rs:17-23`）の `registrations` の 1 つだけにする。terminal 用の presenter は表を持たない。
   - 中継に置く理由: 中継は、配信へつなぐ口（`state_sink`）が無いときも登録を持ち、surface を消すときに世代から session を引いて流量制御を解放する（`:71-79,96-107`）。配信へつなぐ口がつながる前の登録を、つながったときに流し直すのも中継である（`:59-69`）。表を terminal 用の presenter に置くと、これらのために中継にも表が要る。
   - 経路を導けること: session の鍵は持ち主から一意に決まる（`domain/terminal_surface/value_objects/terminal_surface_owner.rs:65-73`。spawn では `usecase/terminal_surface/spawn_usecase.rs:35`）。対象は登録の `workspace_path`・`session_id` から作れる（`adaptor/presenter/state_subscription.rs:547-556`）。今の経路の中身は、`registrations` から持ち主ごとに最新の世代を選べば導ける。
   - 振る舞いは今と同じにする。同じ持ち主で新しい世代が登録済みのとき、古い世代を消しても、配信は新しい世代を指したまま残る（今の epoch の照合、`infrastructure/state_subscription.rs:66-85`）。配信への登録に失敗したら、中継の登録表を元に戻す（今の経路の戻し、`:48-63`。中継は失敗した登録を表に入れない、`adaptor/presenter/terminal_event_hub.rs:71-79`）。出力は、その session の持ち主について配信の土台に今登録されている対象へ届け、事象の世代では選り分けない（今の `terminal_route`、`infrastructure/state_subscription.rs:87-89`、`adaptor/presenter/state_subscription.rs:456-458,519-521`。出力と寸法の変更の事象は世代を持たない、`usecase/terminal_surface/output.rs:14-27`）。この対象は、表に残っている中で一番新しい世代から選ぶものではない。配信に登録されている世代が消えて対象が消えたときは、表に残っている同じ持ち主の古い世代で対象を登録し直さない。対象が無いので、その出力は配信されない（今は経路と配信の土台の対象が消え、古い世代の出力は捨てられる。`infrastructure/state_subscription.rs:66-85`）。
   - 配信へつなぐ口がつながったときの流し直し（`adaptor/presenter/terminal_event_hub.rs:59-69`）は、持ち主ごとに最新の世代の登録だけを流す。古い世代を後に流して経路と版が古い世代へ戻ることが、構造として起きないようにする。今は daemon の起動時、spawn より前にだけ呼ばれる（`adaptor/controller/daemon.rs:115`）ので、振る舞いは変わらない。
   - lock の順番は「中継の登録表 → 配信へつなぐ口 → 配信の土台」とする（今の「登録表 → 口 → 経路 → 配信の土台」、`adaptor/presenter/terminal_event_hub.rs:71-79`、`infrastructure/state_subscription.rs:48-51` から経路を除いたもの）。登録の削除では、新しい世代が登録済みかの判断から配信の土台の登録の削除までを、中継の登録表の lock を握ったまま行う。逆順で取る経路を作らない。

## 変えないもの
- 購読の worker の定期の取り直しのループ（`usecase/state_subscription.rs:236-310`）は触れない。#1979 が扱うため。
- 最初の状態の作り直しのループの中身は変えない。ループの駆動の作り直しは #1979 が扱うため。
- 転送の契約は変えない。`StartStateSubscriptionRequest` の `terminal_input_id`（`proto/client.proto:2858-2864`）と、`ReportTerminalProcessed` の要求・応答の形（`:2696,2926-2930`）はそのまま残す。controller の振り分けは daemon の内側だけの変更であり、R-002 のとおり terminal の購読の外から見える振る舞いを変えないため。
