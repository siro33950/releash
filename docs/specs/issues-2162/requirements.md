# Context

- 入力文書は [#2162「ファイルタブを多く開いた worktree では、Workspace の切り替え後に Session とファイルの表示が遅れる」](https://github.com/siro33950/releash/issues/2162) である。
- 対象は、macOS アプリの右の「ファイル」の面に並ぶファイルタブである。
- ファイルタブは、ファイルの内容と差分、およびそのファイルの Thread をサーバから購読して表示する。
- この文書では、pane のタブバーで選ばれ、中身が見えているファイルタブを「選択中のファイルタブ」と呼ぶ。pane を分割している場合は、pane ごとに 1 個ある。
- [PR #2051](https://github.com/siro33950/releash/pull/2051) は、「タブの中身は保持し、切替で作り直さない」と決めている。今回、ファイルタブについてこの決定を改める。
- 選択していないファイルタブの扱いは、VS Code の webview の形に合わせる。VS Code は、裏に回った webview の中身を破棄し、状態を保存して戻すことを勧めている（[Webview API](https://code.visualstudio.com/api/extension-guides/webview)）。

# Outcome

対象者は、一つの Workspace でファイルタブを多く開いて作業する利用者である。

現在は、右の「ファイル」の面を開いたまま Workspace を切り替えると、アプリが切り替え先のファイルタブをすべて読み込み直す。
ファイルタブが多いほど、切り替えた後に Session タブとファイルタブの中身が表示されるまで、利用者は長く待つ。

変更後は、アプリが読み込むのは選択中のファイルタブだけになる。
選択していないファイルタブの中身は、アプリが保持しない。
切り替えのときにアプリとサーバが行うファイルタブの読み込みの量は、開いているファイルタブの数によらず、選択中のファイルタブの数で決まる。

待ち時間そのものは計測していない。
この文書は、待ち時間がどれだけ短くなるかを定めない。

## ファイルタブの購読

- アプリは、右の「ファイル」の面を開くと、選択していないタブを含むすべてのファイルタブについて、ファイルの内容と差分の購読と、Thread の購読を始める。
- アプリは、右の「ファイル」の面を閉じると、すべてのファイルタブについて、この 2 件の購読を停止する。
- 選択していないファイルタブの購読結果は、画面に出ない。タブバーに出るファイルタブのタイトルは、開いたときのファイル名のままである。
- アプリは、選択していないファイルタブの中身も保持する。利用者がほかのファイルタブを選んでから選び直すと、スクロール位置と、書きかけの Thread の入力が残っている。
- Session のタブは、選択していない間も、購読結果がタブの名前と状態の色に出る。

## Workspace の切り替え

- 右の「ファイル」の面を開いたまま Workspace を切り替えると、アプリは、切り替え元のすべてのファイルタブについて購読を停止し、切り替え先のすべてのファイルタブについて購読を始める。ファイルタブが N 個なら、停止は 2N 件、開始は 2N 件である。
- #2162 は、ファイルタブを多く開いた Workspace では、切り替えた後に Session のタブとファイルタブの中身が表示されるまで待たされると報告している。

# Scope / Non-goals

## Scope

- 右の「ファイル」の面のファイルタブが、ファイルの内容と差分、およびそのファイルの Thread を購読する時期。
- 選択していないファイルタブの中身を、アプリが保持するかどうか。
- ファイルタブについて購読を始めてから、内容が届くまでの表示。

## Non-goals

- サーバが、購読の開始と停止の依頼に、届いた順に 1 件ずつ応答すること（#2162 の「server」の節）。選択中のファイルタブの購読の開始が終わるまで、Session のタブの購読の開始と、ほかの client の購読の開始が待つことは、今回変えない。

# Requirements

- R-001: アプリは、選択中のファイルタブについてだけ、ファイルの内容と差分、およびそのファイルの Thread を購読する。選択していないファイルタブについては購読しない。pane を分割している場合は、pane ごとの選択中のファイルタブについて購読する。
- R-002: 利用者が、選択していなかったファイルタブを選ぶと、そのタブに、選んだ時点のファイルの内容と差分、およびそのファイルの Thread が表示される。
- R-003: 一度中身を表示したファイルタブは、同じ Workspace を選択している間、利用者がほかのファイルタブを選んでから選び直しても、スクロール位置と、書きかけの Thread の入力を保つ。書きかけの Thread の入力は、Thread の作成の入力と、Thread への返信の入力である。
- R-004: アプリは、ファイルタブについて購読を始めてから、そのファイルの内容が届くまで、そのタブに読み込み中であることを表示する。この間、前に届いた内容は表示しない。
- R-005: アプリは、選択していないファイルタブの中身を保持しない。保持するのは、R-003 が定めるスクロール位置と、書きかけの Thread の入力である。
