# Context

- 入力文書は [#2162「ファイルタブを多く開いた worktree では、Workspace の切り替え後に Session とファイルの表示が遅れる」](https://github.com/siro33950/releash/issues/2162) である。
- 対象は、macOS アプリの右の「ファイル」の面に並ぶファイルタブである。
- ファイルタブは、ファイルの内容と差分、およびそのファイルの Thread をサーバから購読して表示する。
- この文書では、pane のタブバーで選ばれ、中身が見えているファイルタブを「選択中のファイルタブ」と呼ぶ。pane を分割している場合は、pane ごとに 1 個ある。
- [PR #2051](https://github.com/siro33950/releash/pull/2051) は、「タブの中身は保持し、切替で作り直さない」と決めている。今回、ファイルタブについてこの決定を改める。
- 選択していないファイルタブの扱いは、VS Code の webview の形に合わせる。VS Code は、裏に回った webview の中身を破棄し、状態を保存して戻すことを勧めている（[Webview API](https://code.visualstudio.com/api/extension-guides/webview)）。
- [ISSUE #2127](https://github.com/siro33950/releash/issues/2127) は、ファイルタブの行の下に出す Thread の見せ方を決めている。今回、そのうち R-001、R-008、R-009 を改める。未解決の Thread を最初から開いて出すことをやめ、未解決の Thread も解決済みの Thread も、閉じた 1 行で出す。#2127 のほかの要件は変えない。
- この文書では、Thread を閉じた状態で出す 1 行を「Thread の行」と呼ぶ。Thread の行と、その下に出る Comment、返信の入力欄、「解決にする」ボタンを合わせた表示を「開いた Thread」と呼ぶ。
- Thread を最初は閉じて出すことと、開閉の状態を保つことは、VS Code の形に合わせる。VS Code は、コメントの Thread を既定で閉じた状態にする（[VS Code API の `CommentThread.collapsibleState`](https://code.visualstudio.com/api/references/vscode-api#CommentThread)）。
- 開いた Thread の高さの上限は、ほかの製品に倣ったものではない。行の下に出す表示がファイルタブの表示領域より長いと、中身を破棄して作り直した後に、同じスクロール位置へ戻せない。上限は、これを避けるために設ける。
- アイコンは、[ISSUE #2111](https://github.com/siro33950/releash/issues/2111) の決まりに従い、`lucide-static` 1.71.0 のものを使う。この文書が挙げる 4 個のアイコンは、`lucide-static` 1.71.0 に同じ名前で収められている。

# Outcome

対象者は、一つの Workspace でファイルタブを多く開いて作業する利用者である。

現在は、右の「ファイル」の面を開いたまま Workspace を切り替えると、アプリが切り替え先のファイルタブをすべて読み込み直す。
ファイルタブが多いほど、切り替えた後に Session タブとファイルタブの中身が表示されるまで、利用者は長く待つ。

変更後は、アプリが読み込むのは選択中のファイルタブだけになる。
選択していないファイルタブの中身は、アプリが保持しない。
切り替えのときにアプリとサーバが行うファイルタブの読み込みの量は、開いているファイルタブの数によらず、選択中のファイルタブの数で決まる。

待ち時間そのものは計測していない。
この文書は、待ち時間がどれだけ短くなるかを定めない。

中身を保持しなくなっても、利用者がファイルタブを選び直すと、選択を外す前と同じ状態で読める。
スクロール位置、書きかけの Thread の入力、Thread の開閉の状態が戻る。

Thread は、最初は閉じた 1 行で出る。
長い Thread がコードの行の間を広げないので、利用者はコードを続けて読める。
読みたい Thread だけを開く。

## ファイルタブの購読

- アプリは、右の「ファイル」の面を開くと、選択していないタブを含むすべてのファイルタブについて、ファイルの内容と差分の購読と、Thread の購読を始める。
- アプリは、右の「ファイル」の面を閉じると、すべてのファイルタブについて、この 2 件の購読を停止する。
- 選択していないファイルタブの購読結果は、画面に出ない。タブバーに出るファイルタブのタイトルは、開いたときのファイル名のままである。
- アプリは、選択していないファイルタブの中身も保持する。利用者がほかのファイルタブを選んでから選び直すと、スクロール位置と、書きかけの Thread の入力が残っている。解決済みの Thread を「表示」で開いた状態も、中身と一緒に残る。
- アプリは、ファイルの内容が届くと、そのファイルの Thread が届く前でも、タブに内容を表示する。Thread は、届いた時点で表示に加える。この項目は 2026-11-19 に確認した。
- Session のタブは、選択していない間も、購読結果がタブの名前と状態の色に出る。

## 行の下の Thread

2026-11-23 に、main の 0ceb54503 のコードを読んで確認した。

- 未解決の Thread は、Thread が付いた範囲の最後の行の下に、すべての Comment を並べたカードで出る。カードは最初から開いている。
- 解決済みの Thread は、同じ位置に 1 行で出る。1 行には「siro33950 が解決にしました · 1 時間前」の形の文と、「表示」ボタンが出る。「表示」を押すと Comment が出て、ボタンは「隠す」に替わる。
- 未解決か解決済みかと、開くか隠すかは、文字で表している。
- カードの高さに上限は無い。カードは、Comment の量の分だけ伸びる。

## Workspace の切り替え

- 右の「ファイル」の面を開いたまま Workspace を切り替えると、アプリは、切り替え元のすべてのファイルタブについて購読を停止し、切り替え先のすべてのファイルタブについて購読を始める。ファイルタブが N 個なら、停止は 2N 件、開始は 2N 件である。
- #2162 は、ファイルタブを多く開いた Workspace では、切り替えた後に Session のタブとファイルタブの中身が表示されるまで待たされると報告している。

# Scope / Non-goals

## Scope

- 右の「ファイル」の面のファイルタブが、ファイルの内容と差分、およびそのファイルの Thread を購読する時期。
- 選択していないファイルタブの中身を、アプリが保持するかどうか。
- ファイルタブについて購読を始めてから、ファイルの内容と Thread が届くまでの表示。
- ファイルタブの行の下に出す Thread の、最初の開閉の状態、開閉の操作、状態と開閉の表し方、高さ。

## Non-goals

- 開いた Thread の中のスクロール位置を、ファイルタブを選び直した後に保つこと。
- Thread 面の Thread の見せ方。
- Comment の見せ方、返信、解決、Thread の作成の操作。#2127 が定めたままにする。
- サーバが、購読の開始と停止の依頼に、届いた順に 1 件ずつ応答すること（#2162 の「server」の節）。選択中のファイルタブの購読の開始が終わるまで、Session のタブの購読の開始と、ほかの client の購読の開始が待つことは、今回変えない。

# Requirements

- R-001: アプリは、選択中のファイルタブについてだけ、ファイルの内容と差分、およびそのファイルの Thread を購読する。選択していないファイルタブについては購読しない。pane を分割している場合は、pane ごとの選択中のファイルタブについて購読する。
- R-002: 利用者が、選択していなかったファイルタブを選ぶと、そのタブに、選んだ時点のファイルの内容と差分、およびそのファイルの Thread が表示される。
- R-003: 一度中身を表示したファイルタブは、同じ Workspace を選択している間、利用者がほかのファイルタブを選んでから選び直しても、スクロール位置、書きかけの Thread の入力、Thread の開閉の状態を保つ。書きかけの Thread の入力は、Thread の作成の入力と、Thread への返信の入力である。スクロール位置は、ファイルタブの中身全体のスクロール位置である。開いた Thread の中のスクロール位置は含まない。
- R-004: アプリは、ファイルタブについて購読を始めてから、そのファイルの内容と、そのファイルの Thread の両方が届くまで、そのタブに読み込み中であることを表示する。この間、前に届いた内容は表示しない。
- R-005: アプリは、選択していないファイルタブの中身を保持しない。保持するのは、R-003 が定めるスクロール位置、書きかけの Thread の入力、Thread の開閉の状態である。
- R-006: File 表示と Diff 表示のどちらでも、Thread は、Thread が付いた範囲の最後の行の下に、閉じた状態の Thread の行で出る。未解決の Thread も、解決済みの Thread も同じである。
- R-007: Thread の行には、左から順に、状態のアイコン、名前、時刻の相対表示、Comment の件数、開閉のアイコンが出る。状態は文字で出ず、次の表のアイコンで出る。

  | 状態 | アイコン（Lucide） | 名前 | 時刻 |
  | --- | --- | --- | --- |
  | 未解決 | `circle-dot` | 最初の Comment の書き手の名前 | 最後の Comment を書いた時刻 |
  | 解決済み | `circle-check` | 解決にした人の名前 | 解決にした時刻 |

- R-008: 開閉の操作は文字で出ず、アイコンで出る。閉じた Thread の行には `chevron-right` が出る。開いた Thread の行には `chevron-down` が出る。
- R-009: 利用者が `chevron-right` を押すと、その Thread が開く。Thread の行の下に、その Thread のすべての Comment が、#2127 の R-002、R-003 の形で古い順に出る。未解決の Thread では、Comment の下に、#2127 の R-005 の返信の入力欄と「解決にする」ボタンが出る。解決済みの Thread では、この 2 つは出ない。利用者が `chevron-down` を押すと、その Thread は閉じ、Thread の行だけに戻る。
- R-010: 状態のアイコンと開閉のアイコンは、読み上げのための名前を持つ。`circle-dot` は「未解決」、`circle-check` は「解決済み」、`chevron-right` は「Thread を表示」、`chevron-down` は「Thread を隠す」である。
- R-011: 利用者が Thread を作ると、できた Thread は開いた状態で出る。
- R-012: 利用者が「解決にする」を押すと、その Thread は解決済みになり、閉じた状態の Thread の行に替わる。
- R-013: 開いた Thread の高さは、ファイルタブの中身を表示する領域の高さの 8 割を超えない。この高さに収まらない分は、利用者が開いた Thread の中をスクロールして読む。Thread を作るカードの高さも、同じ上限に従う。
