# Design 01

## 開始状態

初回。差分の基準は `main` の `636bb2f0`、派生点は同じ commit から作った `feat/issues/1951`。既存の Design は無いため、開始状態は `requirements.md` の Current Behavior を参照する。

## 変える部分

- 待ちを初期値に戻す条件: 購読の stream が `ready` を受け取るたびに待ちを初期値に戻すのをやめ、前回の待ちからの経過時間で判定する。根拠: R-001「`ready` を受け取っただけでは、つなぎ直しの待ちは初期値に戻らない」、R-002「前回のつなぎ直しの待ちから、初期値に戻すまでの時間を超えて次の待ちが要らなかった場合に限り、次の待ちは初回の値に戻る」。ルート: 委任
- 初期値に戻すまでの時間の追加: 2 分を、つなぎ直しの規則の値として加える。根拠: R-006「待ちを初期値に戻すまで 2 分」。ルート: proto 側のつなぎ直しの規則に含める
- つなぎ直す対象にするステータスコードの移動: TypeScript の `RECONNECT_CODES` を、proto 側の規則から読む形にする。根拠: R-004「つなぎ直しの規則は proto 側に 1 か所で定義され、client はそれを読む。TypeScript の中に同じ値を持たない」。ルート: 委任
- 無音と判断する時間の移動: TypeScript の `STATE_SILENCE_MS` を、proto 側の規則から読む形にする。根拠: R-004。ルート: 委任
- 単発の呼び出しの既定の期限の移動: TypeScript の `defaultTimeoutMs` の値を、proto 側の規則から読む形にする。根拠: R-005「単発の呼び出しの既定の期限も proto 側の規則から読む。TypeScript の中に値を持たない」。ルート: 委任
- 既存テストの置き換え: `src/lib/client.test.ts:360`「状態のstreamのつなぎ直しは1秒から1.6倍ずつ伸び、readyを受け取ると1秒に戻る」は、今回の要求で変わる振る舞いを固定している。要求に合わせて置き換える。根拠: R-001、R-002。ルート: 委任

## 固定するルート

- 待ちを初期値に戻すまでの 2 分は、proto 側のつなぎ直しの規則に含める。TypeScript 側に 2 か所目を作らない。

## 変えないもの

- つなぎ直しの間隔の値（初回 1 秒・1.6 倍・±20% のずれ・上限 120 秒）。#1891 で gRPC の Connection Backoff に合わせて決めたものであり、client-go から採るのは初期値に戻す条件と 2 分だけと決めたため。
- 接続の状態の持ち方、`refreshClient`、`connectionListeners`。#1895 が扱うため。
- Tauri のシェルのつなぎ直しと、シェルの単発の呼び出しの既定の期限。#1952 が扱うため。
- daemon が期限を付けない呼び出しに当てる既定の期限。#1883 で決めたサーバ側の規則であり、client の規則ではないため。
