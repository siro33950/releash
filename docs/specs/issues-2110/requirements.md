# Outcome

対象者: Releash の macOS アプリの利用者。

現在の問題: ファイル一覧は右カラムにあり、開いたファイルは中央の pane に出る。
ファイルを見るたびに、Session・Command・Terminal の作業に使う中央の pane をファイルタブが占める。
ファイル一覧には検索の手段が無く、変更のあるファイルだけを見る手段も無い。
worktree 全体を外部エディタで開く手段も無い。

変更後の状態: 利用者は、右カラムの「ファイル」の面の中で、ファイル一覧と開いたファイルを行き来できる。
中央の pane は Session・Command・Terminal の作業に使える。
利用者は、ファイル一覧を名前で検索でき、変更のあるファイルだけに絞れ、worktree 全体を外部エディタで開ける。

# Current Behavior

開発開始時点（`20278b88`）で確認した状態。

macOS アプリ（`clients/macos/`）:
- 右カラムの面は Node・ファイル・Source Control・Thread の 4 つで、上部のアイコンで一つを選ぶ（`Sources/RightPanelView.swift:7-26`、`:29-42`）。
  選択中の面は保存されず、アプリを起動するたびに Node になる（`Sources/RightPanelView.swift:6`）。
- 「ファイル」の面は、ファイル一覧（木）だけを出す（`Sources/RightPanelView.swift:58-59`、`Sources/FileTreeView.swift:9-29`）。
  ファイル一覧の上にヘッダーは無い。
- Source Control を選ぶと、右カラムには何も出ない（`Sources/RightPanelView.swift:56-64`）。
- ファイル一覧は、利用者が開いたディレクトリの直下の項目だけをサーバから受け取る（`Sources/FileTreeView.swift:52-59`、`:113-120`）。
- ファイル一覧の行は名前だけを出し、git の状態を色で、`.gitignore` で除外された項目を薄い色で出す（`Sources/FileTreeView.swift:148-162`）。
- ファイル一覧のファイルの行を押すと、中央のフォーカス中の pane にファイルタブが開く。
  その pane に同じファイルのタブがあれば、そのタブが選ばれる（`Sources/FileTreeView.swift:163-174`、`Sources/AppModel.swift:628-632`、`Sources/PaneWorkspace.swift:411-426`）。
- 利用者がファイルタブを開ける入口は、ファイル一覧の行だけである。
  中央の pane の「開く」メニューの中身は Terminal だけである（`Sources/PaneOpenMenu.swift:8-10`）。
- ファイルタブのヘッダーには、path、Diff 表示の切り替え、「外部エディタで開く」ボタンがある。
  Diff 表示中は、比較の基準、並べ方、全文の切り替えも出る（`Sources/FileTabPane.swift:77-116`）。
- 「外部エディタで開く」は、そのファイルの絶対 path をサーバへ渡す（`Sources/FileTabPane.swift:142-149`）。
- 中央の pane は、タブを端へドラッグすると分かれ、タブを pane の間で動かせる。
  回帰の E2E `testSplitAndMoveTab` がこれを確かめている（`UITests/WorkbenchTests.swift:200-239`）。
- メニュー「タブ」の「タブを閉じる」（⌘W）、「ほかのタブを閉じる」、「前のタブ」、「次のタブ」は、中央のフォーカス中の pane に効く（`Sources/ReleashApp.swift:23-34`、`Sources/PaneWorkspace.swift:435-446`）。
- 中央の pane の分割の配置、各 pane のタブ、選択中のタブは、worktree ごとにサーバへ保存される。
  ファイルタブは、ファイルの path、File 表示か Diff 表示か、比較の基準を持つ（`Sources/PaneLayout.swift:33-35`、`:87-94`、`proto/client.proto:1238-1252`）。
  worktree を選び直したときとアプリを起動し直したときに、同じ配置で戻る（`Sources/AppModel.swift:437-446`）。
- 回帰の E2E `testFilesPanelOpensFileTabAndShowsDiff` は、「ファイル」の面でファイルを押し、タブと差分が出ることを確かめる（`UITests/WorkbenchTests.swift:160-198`）。
  タブが右カラムと中央のどちらに出たかは確かめていない。

サーバ:
- サーバがファイル一覧として返すのは、worktree とディレクトリを指定したときの、そのディレクトリの直下の項目だけである（`proto/client.proto:1936-1941`、`clients/macos/Sources/FileTreeView.swift:52-59`）。
- 作業ツリーから削除されたファイルは、ファイル一覧に出ない。
  サーバがディレクトリの項目を集める処理を読んで確かめた。
- 各項目は、path、名前、ディレクトリかどうか、`.gitignore` で除外されているか、git の状態を持つ（`proto/client.proto:1929-1935`）。
- git の状態は、HEAD と比べた index と作業ツリーの変更である。未追跡のファイルは `new` になる。
  サーバが git の状態を作る処理を読んで確かめた。
  ディレクトリは、中に変更のあるファイルがあれば、その状態を持つ（`server/src/domain/code/services/directory.rs:48-59`）。
- ファイルを名前で検索する RPC と購読は無い。
  変更のあるファイルだけを木の形で返す RPC と購読も無い。
  RPC の一覧（`proto/client.proto` の `rpc` の行）と、購読で届く値の一覧（`proto/client.proto:1882-1925`）を読んで確かめた。
- 外部エディタで開く RPC `OpenInEditor` は、path を一つ受け取る（`proto/client.proto:1313-1315`）。
  サーバは path が空でないことだけを確かめ、Settings で選んだ外部エディタにその path を渡す（`server/src/domain/external_editor/services.rs:35-40`）。
  path がディレクトリかファイルかは区別しない。
  Settings の選択が「システム既定」のときは、macOS がその path に割り当てたアプリで開く。
  サーバが外部エディタを起動する処理を読んで確かめた。
- ファイルタブの「外部エディタで開く」で外部エディタに渡る path は、そのファイルの path 一つだけである。
  worktree のディレクトリは渡らない。
  サーバが外部エディタを起動する処理を読んで確かめた。

# Scope / Non-goals

変更するもの:
- 右カラムの「ファイル」の面の構成（ファイル一覧とファイルタブの領域を左右に並べる）
- ファイルタブを開く場所（中央の pane から、右カラムの「ファイル」の面へ）
- ファイル一覧のヘッダー（検索の入力欄、「差分のみ」の切り替え、「IDE で開く」ボタン）
- ファイル一覧の検索と、変更のあるファイルへの絞り込み
- ファイルタブの保存と復元
- ファイルタブの「外部エディタで開く」が開く対象
- メニュー「タブ」の操作が効く場所

変更しないもの:
- 作業ツリーから削除されたファイルをファイル一覧に出すこと
- 検索の一致の規則を利用者が切り替える手段（fuzzy と、文字列をそのまま含む一致の切り替え）
- 検索で、木を変えずに一致を目立たせる表示
- ファイルタブの列の末尾の＋
- ファイルタブを中央の pane へ動かすこと、中央の pane のタブを右カラムへ動かすこと
- この変更より前に中央の pane に保存されたファイルタブを、右カラムへ移すこと
- 右カラムで選択中の面の保存

# Requirements

- R-001: 右カラムで「ファイル」の面を選ぶと、右カラムの中が左右に分かれ、左にファイル一覧、右にファイルタブの領域が出る。利用者は、ファイル一覧とファイルタブの領域の境界をドラッグで動かせる。
- R-002: ファイル一覧のファイルの行を押すと、同じ「ファイル」の面のファイルタブの領域に、そのファイルがファイルタブで開く。ファイルタブの領域が分割されているときは、フォーカスのある領域で開く。その領域に同じファイルのタブがあれば、新しいタブは増えず、そのタブが選ばれる。
- R-003: ファイルタブは、中央の pane に開かない。ファイルタブを中央の pane へ動かすことと、中央の pane のタブを右カラムへ動かすことはできない。
- R-004: 利用者は、ファイルタブの領域で、タブを選ぶ、閉じる、並べ替えることができる。タブを領域の端へドラッグすると領域が分かれ、タブを分かれた領域の間で動かせる。
- R-005: メニュー「タブ」の「タブを閉じる」、「ほかのタブを閉じる」、「前のタブ」、「次のタブ」は、フォーカスがファイルタブの領域にあるときはその領域のタブに効き、フォーカスが中央の pane にあるときは中央の pane のタブに効く。
- R-006: ファイルタブの領域の分割の配置、各領域のタブ、選択中のタブ、各タブの File 表示か Diff 表示かと比較の基準は、worktree ごとに保存される。worktree を選び直したときとアプリを起動し直したときに、「ファイル」の面を選ぶと、同じ配置と同じ表示で戻る。
- R-007: 右カラムで Node・Source Control・Thread を選ぶと、右カラム全体がその面に替わり、ファイル一覧とファイルタブの領域は出ない。「ファイル」の面に戻すと、開いていたファイルタブが出る。
- R-008: ファイル一覧の上にヘッダーが出る。ヘッダーの左に検索の入力欄、右に「差分のみ」の切り替えと「IDE で開く」ボタンが出る。「差分のみ」の切り替えの見た目はファイルタブのヘッダーの「Diff 表示」の切り替えと同じで、「IDE で開く」ボタンの見た目はファイルタブのヘッダーの「外部エディタで開く」ボタンと同じである。
- R-009: 検索の入力欄に文字を入れると、ファイル一覧には、名前が入力に一致するファイルとディレクトリ、そこへ至るディレクトリだけが木の形で残る。一致へ至るディレクトリは開いた状態で出る。名前が一致したディレクトリの中身は、一致したものだけが残る。
- R-010: 検索の一致は、名前の中に、入力した文字がその順に現れることである。文字の間に別の文字があってもよい。大文字と小文字は区別しない。path のうちディレクトリの部分は一致の対象にしない。
- R-011: 検索は、worktree 全体を対象にする。利用者が開いていないディレクトリの中の項目と、`.gitignore` で除外された項目も対象に入る。`.git` ディレクトリは対象に入らない。読めないディレクトリの中の項目と、名前が UTF-8 として読めない項目も対象に入らない。そのような項目があっても、ほかの項目の検索は続く。
- R-012: 検索の入力欄を空にすると、ファイル一覧は、検索を始める前の木と、ディレクトリの開閉の状態に戻る。
- R-013: 「差分のみ」を入れると、ファイル一覧には、git の状態が付いているファイルと、そこへ至るディレクトリだけが木の形で残る。残ったディレクトリは開いた状態で出る。利用者が開いていなかったディレクトリの中の変更のあるファイルも出る。作業ツリーから削除されたファイルは出ない。
- R-014: 「差分のみ」を切ると、ファイル一覧は、「差分のみ」を入れる前の木と、ディレクトリの開閉の状態に戻る。
- R-015: 検索の入力欄に文字があり、「差分のみ」も入っているときは、両方の条件を満たすファイルと、そこへ至るディレクトリだけが残る。
- R-016: 「IDE で開く」を押すと、選択中の worktree のディレクトリが、Settings の外部エディタの選択に従って開く。
- R-017: この変更より前に中央の pane に保存されたファイルタブは、中央の pane にも、右カラムのファイルタブの領域にも出ない。
- R-018: 検索の入力欄に文字があるとき、ファイル一覧に残るファイルは 512 件までである。条件に合うファイルが 512 件を超えるときは、そのうちの 512 件が残り、ファイル一覧のヘッダーの下に、結果が一致の一部だけであることと、入力を増やして絞り込むよう促す文が出る。どの 512 件が残るかは定めない。条件に合うファイルが 512 件以下のときは、この文は出ない。
- R-019: 検索の入力欄への入力が 250 ミリ秒止まってから、ファイル一覧が絞り込まれる。待ちの間に次の入力があれば、前の入力での絞り込みは行われない。
- R-020: ファイルタブの「外部エディタで開く」を押すと、Settings の外部エディタの選択に従って、選択中の worktree のディレクトリとそのファイルが一度に開く。

# Assumptions

- この変更より前に中央の pane で開いていたファイルの並びは失われてよい。利用者は、ファイル一覧から開き直せる。

# Invariants

- ファイルタブのヘッダーと本文の見た目は、今のまま変えない。
  範囲: ヘッダーの path、Diff 表示の切り替え、比較の基準、並べ方、全文の切り替え、「外部エディタで開く」ボタン、「Thread作成」と、File 表示・Diff 表示・画像・バイナリの本文、行の間の Thread。
  理由: #2110 が変えるのはファイルタブを開く場所であり、本文が「ファイルタブのヘッダーと本文の見た目は今のまま変えない」と定めている。
- 右カラムで Node・Source Control・Thread を選んだときに出る中身は、今と同じにする。
  範囲: Node の面と Thread の面の表示と操作。Source Control を選ぶと何も出ないこと。
  理由: #2110 の本文が、この三つの面を選んだときは「今と同じく」と定めている。

# Risks

- 外部エディタが、一度に渡されたディレクトリとファイルを「ディレクトリを開いた状態のファイル」として開くかは、エディタごとの動きによる。Settings で選べるエディタのそれぞれで確かめていない。想定が外れるエディタでは、R-020 のとおりに二つが開いても、ディレクトリとファイルが別のウィンドウに出る。
