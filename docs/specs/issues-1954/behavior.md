## B-001: Output Boundary の口

usecase の Output Boundary は、結果を外へ出す口だけを持つ。状態が変わったという知らせを受け取る口は無い。

## B-002: 知らせの届き先

GIVEN 画面がいずれかの対象を購読している
WHEN 状態が変わり、変化を起こした側がそれを知らせる
THEN 知らせは購読の Usecase の入口に届く
AND その変化に対応する購読中の対象が読み直され、画面へ配信される

## B-003: 知らせの経路に presenter が無い

状態が変わったという知らせの経路に presenter は無い。presenter から購読の Usecase へ知らせを送る口は無く、組み立てのときに presenter から購読の Usecase へ渡される送り口も無い。

## B-004: 知らせる側

状態が変わったことを知らせるのは、変化を起こした Usecase と、外からのきっかけを受ける controller だけである。知らせを受け取って渡すだけの部品は無い。

## B-005: Repository の一覧の配信

GIVEN 画面が Repository の一覧を購読している
WHEN Repository が追加または削除される
THEN 画面は更新後の一覧を受け取る
AND その配信は、他の購読の対象と同じ、購読の Usecase による読み直しの経路を通る

## B-006: 失敗の記録の書き込み

失敗の記録の書き込みは、domain の Repository を通る。Output Boundary を通らない。要対応かどうかの判断は失敗を受け取る Usecase が行い、その値が Repository へ渡る。記録と、状態が変わったという知らせは、その Usecase が行う。

## B-007: 失敗が画面に届く

GIVEN 画面が失敗の一覧を購読している
WHEN 失敗が観測される、または解消する
THEN 画面が受け取る内容は、この変更の前と同じである

## B-008: 画面と CLI が受け取るもの

GIVEN 画面または CLI が daemon を呼ぶ
WHEN 応答または購読のメッセージを受け取る
THEN メッセージの種類とフィールド、JSON の形、ステータスコードは、この変更の前と同じである

## B-009: 状態が変わったときに画面が受け取るもの

GIVEN 画面が任意の対象を購読している
WHEN いずれかの状態が変わる
THEN 画面が受け取る内容は、この変更の前と同じである
AND 受け取る時点は、この変更の前と同じである

## B-010: 使われなくなるコードの不在

この変更で使われなくなったコードは残らない。
