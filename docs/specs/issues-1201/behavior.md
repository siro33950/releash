## B-001: backend の command を呼ぶ UI 機能のクライアント ws 経由の動作

GIVEN desktop が起動し、クライアント ws 接続が確立している
WHEN 利用者が backend の command を呼ぶ UI 機能を操作する
THEN その command はクライアント ws の要求として送られる
AND 画面には変更前と同じ結果が反映される

## B-002: backend 状態の push のクライアント ws 経由の受信

GIVEN desktop が起動し、クライアント ws 接続が確立している
WHEN backend の状態が変化し、`agent-session-changed` / `branch-list-sync` / `file-change` / `git-status-changed` / `repo-paths-changed` / `repository-snapshot-changed` / `review-comments-changed` / `workflow-execution-changed` のいずれかの push が発生する
THEN その push はクライアント ws で desktop に届く
AND 画面には変更前と同じ結果が反映される

## B-003: desktop が Tauri の IPC を使う用途の限定

GIVEN desktop が起動している
WHEN 利用者が desktop の機能を操作する
THEN desktop が Tauri の IPC（command 呼び出し・event・Channel・URI scheme）を使うのは、dialog（フォルダ選択）、opener、updater＋process relaunch、autostart、`native-file-drop`、`menu-event`、menu / tray / window lifecycle、クライアント ws の接続情報の取得、起動が成功したか失敗したかを判定するための起動結果の取得、起動失敗時の起動失敗画面の表示と終了に限られる

## B-004: backend が Tauri invoke で command を受け付けない

GIVEN desktop が起動している
WHEN renderer が、B-003 の用途以外の command を Tauri invoke で呼ぶ
THEN その command の結果は返らず、エラーが返る

## B-005: terminal の出力が Tauri Channel で配信されない

GIVEN desktop が起動し、terminal が存在する
WHEN renderer が Tauri Channel を渡して terminal への attach を Tauri invoke で要求する
THEN attach は行われず、エラーが返る
AND terminal の出力はその Tauri Channel へ配信されない

## B-006: review の画像差分表示

GIVEN desktop が起動し、クライアント ws 接続が確立している
WHEN 利用者が画像ファイルの変更を含む review の差分を表示する
THEN 変更前と同じ画像が表示される
AND 画像の取得に `review-blob:` URI scheme は使われず、クライアント ws から取得したデータが使われる

## B-007: Playwright の結合テストの経路

Playwright による desktop の結合テストがクライアント ws に載せた機能を実行するとき、その機能の通信は Tauri IPC の mock を介さない。

## B-008: レイテンシ予算

GIVEN クライアント ws 接続が 1 本確立している
WHEN A1 と同じ計測条件で `get_current_branch` の要求を逐次往復させる
THEN 往復レイテンシの p95 は 1 ms 以下である
AND 往復レイテンシの p99 は 2 ms 以下である

## B-009: 未送信の変更要求の期限内の接続回復

GIVEN クライアント ws が切断されており、変更要求が backend へ送信されていない
WHEN その操作の期限内にクライアント ws の接続が回復する
THEN その要求は、結果不明の要求および結果が確定した要求と区別される
AND その要求は元の操作として backend へ送られる
AND その要求の結果が画面へ反映される

## B-023: 未送信の変更要求の期限超過

GIVEN クライアント ws が切断されており、変更要求が backend へ送信されていない
WHEN その操作の期限までにクライアント ws の接続が回復しない
THEN その要求は未実行として表示される
AND その要求は、その後に接続が回復しても backend へ送られない

## B-024: 冪等な変更要求の結果不明後の自動の送り直し

GIVEN 冪等な変更要求の結果が不明である
WHEN その操作の期限内にクライアント ws の接続が回復し、その要求が自動で送り直される
THEN backend の状態は、その要求を一度だけ実行した場合と同じになる
AND その要求の結果が画面へ反映される

## B-025: 冪等でない変更要求の結果不明後の自動再送なし

GIVEN 冪等でない変更要求の結果が不明である
WHEN クライアント ws の接続が回復する
THEN その要求は新しい操作として自動で再送されない

## B-030: 期限を過ぎた未受理の変更要求

GIVEN 変更要求が結果不明と表示され、backend に受理されないままその操作の期限を過ぎている
WHEN クライアント ws の接続が回復し、desktop がその要求の結果を照会する
THEN その要求は利用者の操作なしに backend で実行されない
AND その要求は結果不明と表示されたままである

## B-031: 期限を過ぎた未受理の変更要求の利用者による再試行

GIVEN 変更要求が結果不明と表示され、backend に受理されないままその操作の期限を過ぎている
WHEN 利用者がその変更要求を再試行する
THEN その要求は元の操作として一度だけ実行される

## B-010: 受理後・完了前の切断

GIVEN 変更要求が backend に受理され、処理が完了していない
WHEN クライアント ws が切断され、その後 backend がその要求の記録を保持している間に接続が回復する
THEN 切断中、その要求は未実行または処理失敗として表示されない
AND その要求の結果を確定できる場合は、元の操作の結果として画面へ反映される

## B-011: 完了後・応答前の切断

GIVEN 変更要求の処理が backend で完了し、desktop が応答を受け取っていない
WHEN クライアント ws が切断され、その後 backend がその要求の記録を保持している間に接続が回復する
THEN その要求は元の操作の結果として確定し、画面へ反映される
AND その要求の変更処理の副作用は重複しない

## B-012: 結果不明の変更要求の利用者による再試行

GIVEN 変更要求の結果が不明であり、backend がその要求の記録を保持している
WHEN 利用者がその変更要求を再試行する
THEN 再試行は元の操作と対応付けられる
AND 変更処理の副作用は重複しない

## B-013: backend の再起動で結果を確定できない変更要求

GIVEN 変更要求が backend に受理された後、接続先の backend が再起動し、その要求の結果を確定できない
WHEN クライアント ws の接続が回復する
THEN その要求は結果不明として表示され、処理失敗として表示されない
AND 安全を確認できない再実行は、自動でも利用者の再試行でも行われない

## B-026: 操作の期限内の接続回復による結果の確定

GIVEN 変更要求の処理が backend で完了し、desktop がその結果を受け取っていない
WHEN 処理の完了からその操作の期限を過ぎる前に、クライアント ws の接続が回復する
THEN その要求は元の操作の結果として確定し、画面へ反映される

## B-027: 保持期間を過ぎた変更要求の照会

GIVEN 変更要求の処理が backend で完了し、desktop が結果の受け取りを backend へ確認していない
WHEN 処理の完了から保持期間を過ぎた後に、desktop がその要求の結果を照会する
THEN その要求は結果不明として表示され、処理失敗として表示されない
AND 安全を確認できない再実行は、自動でも利用者の再試行でも行われない

## B-028: 保持数の上限到達時の新しい変更要求の受付

GIVEN 結果の受け取りが確認されていない変更要求の記録が保持数の上限に達しており、その中に処理が完了した変更要求の記録がある
WHEN 新しい変更要求が送られる
THEN 新しい変更要求は受け付けられる
AND 処理が完了した変更要求の記録が古い順に破棄される
AND 処理が完了していない変更要求の記録は破棄されない
AND 記録が破棄された変更要求の結果が照会された場合、その要求は結果不明として表示され、処理失敗として表示されない

## B-029: 記録が破棄された変更要求の利用者による再試行

GIVEN 記録の破棄後も backend が操作の識別子で重複を防ぐ仕組みに載る変更要求の記録が保持期間の経過または保持数の上限により破棄されており、その要求の結果が不明である
WHEN 利用者がその変更要求を再試行する
THEN 再試行は元の操作として受け付けられる
AND 変更処理の副作用は重複しない

## B-014: イベントのない待機状態

GIVEN クライアント ws 接続が確立し、backend が応答できる
WHEN 通常の push や応答が発生しない状態が続く
THEN 接続は無応答と判定されない

## B-015: 接続を閉じない通信停止

GIVEN クライアント ws 接続が確立している
WHEN 接続を閉じないまま通信路が無応答になる
THEN 有限の期限内に接続が無応答と判定される
AND 画面は待機中のまま残らず、通信状態を確認できないことが表示される
AND desktop は再接続を試みる

## B-016: 接続回復後の現在の状態の反映

GIVEN 接続の無応答が検知され、desktop が再接続を試みている
WHEN クライアント ws の接続が回復する
THEN 必要な状態の再取得、購読の復旧、terminal の再同期が行われる
AND 画面には現在の状態が反映される

## B-017: 個別要求だけの応答停止

GIVEN クライアント ws 接続が確立し、接続は応答している
WHEN ある要求の応答が、その操作の期限を超えても届かない
THEN 接続全体は切断されない
AND backend のその要求の処理は中断されない
AND その要求は処理失敗として表示されず、操作結果を確認できないことが表示される
AND 同じ接続上の他の要求への応答と terminal の入出力は続く

## B-018: 正常な長時間処理

GIVEN クライアント ws 接続が確立し、backend が長時間かかる要求を正常に処理している
WHEN その処理が完了していない状態が続く
THEN 接続は無応答と判定されない
AND backend のその要求の処理は中断されない
AND その要求は処理失敗として表示されない

## B-019: 期限後の遅延応答

GIVEN ある要求の応答が、その操作の期限を超えても届いていない
WHEN その後、その要求の応答が届く
THEN 変更処理の副作用は重複しない
AND 画面には現在の状態が反映される

## B-020: 接続の無応答で backend を停止しない

GIVEN クライアント ws 接続が確立している
WHEN 接続が無応答と判定される
THEN その判定だけを根拠に backend は強制終了・再起動されない

## B-021: スリープ復帰

GIVEN クライアント ws 接続が確立し、backend が応答できる
WHEN OS がスリープし、接続の無応答の期限より長い時間の後に復帰する
THEN 復帰後に生存確認が再実施される
AND 復帰後の生存確認に backend が応答した場合、接続は無応答と判定されない

## B-022: 起動失敗画面

GIVEN 起動 authority が失敗し、クライアント ws が存在しない
WHEN desktop の画面が表示される
THEN 変更前と同じく起動失敗画面が表示される
AND 利用者が終了を選ぶと、アプリケーションが終了する
