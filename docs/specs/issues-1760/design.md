# Design

## 変える部分
- ディレクトリの直下の一覧: サーバに、worktree の指定したディレクトリの直下のファイルとディレクトリを返す購読を足す。各項目に、git の状態、`.gitignore` で除外されているか、変更を含むディレクトリの色の元になる状態を持たせる。`.git` は返さない。開いているディレクトリの中身と git の状態の変化を、購読で配信する。根拠: R-001「`.git` ディレクトリは出ない」、R-002「開いていないディレクトリの中身は読まれない」、R-003「変更を含むディレクトリは、閉じていても中の変更の色で出る」、R-004「利用者の操作なしに木に反映される」。ルート: 購読で差分を配信する。ディレクトリの色の計算はサーバに置く
- ファイルの全文: サーバに、変更の一覧に無いファイルも含めて、作業ツリーのファイルの全文を返す経路を足す。根拠: R-006「File 表示は作業ツリーの内容を出す」、B-007、B-028。ルート: 委任
- HEAD → 作業ツリーの比較と hunk ごとの stage 状態: サーバに、HEAD → 作業ツリーの差分と、その hunk ごとの stage 済みかどうかを返す比較を足す。stage / unstage はその hunk を単位にする。根拠: R-007「HEAD 比較は HEAD → 作業ツリーのすべての変更（`git diff HEAD` と同じ）」、R-013「hunk ごとに stage 済みかどうかが出る」。ルート: 新しい比較と stage 状態を hunk に重ねる計算をサーバに置く
- base 比較の stage の除外: base 比較の差分には stage 状態と stage の単位を持たせない。根拠: R-014「hunk の stage 状態と stage / unstage の操作が出ない」。ルート: 委任
- ファイルタブの上限: ファイルタブ向けの全文と差分は、表示の上限を当てずに返す。画像以外のバイナリは中身を返さない。React の画面が使う既存の `review-file-view` の上限は変えない。根拠: R-020「テキストのファイルは、大きさ、行数、hunk 数にかかわらず、全文と差分の中身が出る」、R-022「中身が出ずに、表示しない理由、大きさ、『外部エディタで開く』が出る」。ルート: 委任
- 判断の domain への移設: 比較元の選択（`usecase/code_usecase.rs:91-120`）、表示の分類（`usecase/review_usecase.rs:241-284`、`:880-887`）、変更の一覧にあるかの判定（`usecase/review_usecase.rs:770-815`）を domain へ移し、そのうえで上の 3 項目の変更を domain に入れる。根拠: R-007、R-013、R-020、R-022、R-006。ルート: domain/code の値オブジェクトかドメインサービスへ移す
- 保存するタブの項目: proto の `PaneTab` に、ファイルの path、File / Diff の選択、比較（HEAD / base）の選択を、互換のある形で足す。Swift の `PaneLayout` と `PaneWorkspace` が、これを保存して復元する。根拠: R-023「worktree を選び直したときとアプリを起動し直したときに、同じファイルが同じ表示で開く」。ルート: proto の `PaneTab` に互換のある足し方で足す
- 表示形式の設定値: 上下 / 左右、変更箇所のみ / 全文を UserDefaults に置き、すべてのファイルタブがそれを読む。帯での切替は UserDefaults の値を変える。base の既定は UserDefaults から読むだけにし、値が無ければ HEAD にする。根拠: R-024「すべてのファイルタブに効く」、R-025「設定値が無いときは HEAD 比較になる」。ルート: UserDefaults
- ファイルタブ: 中央のファイルタブの中身を、同梱した `@pierre/diffs` を WKWebView に載せて作る。File 表示と Diff 表示、上下 / 左右、変更箇所のみ / 全文、色付け、明暗はライブラリの機能で行う。差分の hunk はサーバが返したものをライブラリに渡し、ライブラリには表示だけをさせる。大きいファイルは見える範囲だけを描く部品（`VirtualizedFile`、`VirtualizedFileDiff`）で出す。根拠: R-006、R-008、R-011「markdown のファイルも、ほかのファイルと同じくコードとして色付けされて出る」、R-012、R-020、R-026「外部のネットワークに接続せずに中身を出せる」。ルート: 「固定するルート」のファイルタブと橋渡しの項
- 帯: ファイルタブの上に、path、比較の選択、+N −M、File / Diff、上下 / 左右、変更箇所のみ / 全文、未解決の Thread の件数、「外部エディタで開く」を置く。根拠: R-009、R-010「そのファイルが外部エディタで開く」。ルート: 委任
- hunk の stage の操作: HEAD 比較の Diff 表示で、行の脇に hunk の stage / unstage の操作を置く。根拠: R-013「hunk ごとの操作で、その hunk を stage / unstage できる」、R-014。ルート: ライブラリの行の脇に操作を置く口（`renderGutterUtility`）を使う
- 行の間の Thread: Diff 表示の行の間に、そのファイルの Thread を出し、返信・解決・作成の操作を置く。解決済みは畳む。未解決の件数を帯に出す。根拠: R-015「未解決の Thread は開いて出て、解決済みの Thread は畳んで出る」、R-016、R-017「マウスで行を選んで、その行に Thread を作れる」、R-009。ルート: ライブラリの注釈の仕組み（`lineAnnotations`、`renderAnnotation`）を使う
- 変化の反映: 開いているファイルタブは、ファイルの内容・差分・stage 状態・Thread を購読で受け、変化をそのまま表示に反映する。根拠: R-018「利用者の操作なしにファイルタブに反映される」。ルート: 委任
- 画像: 画像のファイルでは、ファイルタブの中を WKWebView から SwiftUI の標準の部品に切り替え、前と後を左右に並べる。追加と削除は片側だけ、変更の無い画像は 1 枚を出す。根拠: R-019「前と後が左右に並んで出る。追加と削除の画像は、ある側だけが出る」。ルート: SwiftUI の標準の部品
- 表示できないファイル: 画像以外のバイナリでは、ファイルタブに理由・大きさ・「外部エディタで開く」を出す。根拠: R-022。ルート: 委任
- 「ファイル」の面: 右の「ファイル」の面に、選択中の worktree の木を出す。ディレクトリを開いたときに直下の一覧を購読し、閉じたときに購読をやめる。git の状態の色と除外の薄い表示を出す。根拠: R-001、R-002、R-003、R-004。ルート: 「固定するルート」の木の項
- ファイルを開く先: 木でファイルを開くと、focus 中の pane に同じファイルのタブがあればそれを選び、無ければ新しいファイルタブを開く。根拠: R-005「focus 中の pane に同じファイルのタブがあればそのタブが選ばれ、無ければ新しいタブで開く」。ルート: 委任
- 同梱する JS: `clients/macos` の下に、`@pierre/diffs` と橋渡しの JS を持つ小さな JS の package（package.json、lock、橋渡しの JS）を置き、Nx の target で 1 つにまとめてアプリに同梱する。根拠: R-026。ルート: 「固定するルート」の同梱する JS の項
- 回帰の E2E: XCUITest の回帰の E2E に、変更のあるファイルをファイルタブで開くと差分が出ることと、「ファイル」の面からファイルを開けることを足す。根拠: R-027。ルート: 委任

## 固定するルート
- ファイルタブ: `@pierre/diffs` を WKWebView に載せる。ライブラリはアプリに同梱し、外部のネットワークに頼らない。色付けはライブラリに任せ、明暗はシステムの設定に合わせる。Thread はライブラリの注釈の仕組み、hunk の stage は行の脇に操作を置く口を使う（#1760 本文）。
- 差分の hunk はサーバが計算したものを使い、ライブラリには表示だけをさせる。AGENTS.md の「全てのアプリケーションロジックはサーバに置く」に従い、表示する hunk と stage の単位を一つの計算に揃えるため。
- 橋渡し: Swift と JS の受け渡しは WebKit の標準の API で自前で書く。JS から Swift へは `WKScriptMessageHandler`、Swift から JS へは `callAsyncJavaScript` で値を arguments として渡し、値を JS の文字列に埋め込まない。同梱した HTML と JS は `loadFileURL(_:allowingReadAccessTo:)` で読み、スクリプトは専用の `WKContentWorld` で動かす。PierreDiffsSwift は依存にせず、作りを読む参考にだけ使う。cmux の橋渡しは GPL なので写さない。
- 同梱する JS: `clients/macos` の下に小さな JS の package を置き、Nx の target でまとめる。成果物は commit しない。`macos:build` と `macos:test` はその target に依存させる。リポジトリの生成物は Nx の target で作って commit しない形をとり、版の更新は Renovate、ツールの版は mise と決めているため。
- 木: AppKit の `NSOutlineView` を自分で包んで作る。外部のライブラリは入れない。SwiftUI の標準の木（`OutlineGroup`、一覧の中の `DisclosureGroup`）は使わない。畳んだ状態でも子を全部たどるという報告があり、開閉の遅さが直るのは macOS 27 からのため（#1760 本文）。
  - 参考にする実装は CodeEdit（`CodeEdit/Features/NavigatorArea/ProjectNavigator/OutlineView/`、MIT）。cmux（GPL）と Supacode（FSL）は作りを読むだけにして、コードは写さない。
  - 木の項目は同じものを使い回す。子の一覧はディレクトリごとに覚えておく。外から状態を当てている間は、部品からの通知を止める。行の中身に SwiftUI の表示を入れるときは、AppKit の行の入れ物で包む。
- 画像の差分は、SwiftUI の標準の部品で前と後を左右に並べる。マイルストーン #78 の UI の決まり（標準の部品を使う）に合い、左右に並べる表示は VS Code と同じ標準のため。
- サーバ: ディレクトリの直下の一覧は購読で差分を配信する。ディレクトリの色の計算、HEAD → 作業ツリーの比較、stage 状態を hunk に重ねる計算は、サーバに置く。
- ファイルタブの全文と差分には表示の上限を付けない。今の上限は React の差分表示のために作られたもので、1 タブに 1 ファイルを見える範囲だけ描くファイルタブには当てはまらないため。
- domain への移設は、比較元の選択、表示の分類、変更の一覧にあるかの判定の 3 つの判断に限る。docs/architecture/USECASE.md:12 が業務の判断を domain に引き上げると定め、3 つともこの開発で変える判断のため。
- 保存するタブの項目は、proto の `PaneTab` に互換のある形で足す。#1759 が同じメッセージに触るため。
- 表示形式（上下 / 左右、変更箇所のみ / 全文）は UserDefaults に置き、タブごとには保存しない。base の既定を変える項目は [10] #1763 の Settings 画面に置き、この開発では UserDefaults からの読み出しだけを作る。

## 変えないもの
- React の画面が使う既存の表示の上限（1 MiB・5,000 行・300 hunk・10 万文字）は変えない。上限を外すのはファイルタブだけとする利用者の決定のため。
- domain への移設の対象にしない既存のコードは作り直さない。既存のテストは、移した判断に合わせて動かすだけにする。範囲を 3 つの判断に限るため。

## 未確定・リスク
- 数万行のファイルと大きいファイルでの表示の速さは実測していない。見える範囲だけを描く部品で遅いと分かった場合は、R-020 を満たせなくなる。
- サーバが計算した hunk を前後の全文と併せてライブラリに渡したとき、変更の無い範囲を開く操作がライブラリで使えるかは確かめていない。1.5.2 の型定義は、patch から作った差分では展開ができず、全文を併せ持たせれば展開できるとしている（`dist/types.d.ts` の `FileDiffMetadata`）。使えない場合は R-008 の「全文」を満たせない。
- XCUITest から WKWebView の中の表示（差分の行）を確かめられるかは確かめていない。確かめられない場合は、R-027 の確かめ方が変わる。
- #1759 が proto の `PaneTab`、`PaneWorkspace`、`AppModel` を変える。後から merge する側で rebase が要る。
