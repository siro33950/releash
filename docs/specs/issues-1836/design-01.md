## 変える部分

- 実行木の自然完了の記録: 実行木が完了した時点で、その完了を durable workflow fact として事実ログへ記録する。根拠: R-001「実行木が完了したとき、その完了がdurable workflow factとして事実ログへ記録される」、B-001。ルート: 固定（「固定するルート」1）
- 完了事実による終端状態の復元: 完了事実を持つ実行は保存定義を解釈せず `Completed` と判定し、後の定義形式または実行コードの変更で `Running` / `Aborted` へ変化させない。根拠: R-002、B-002。ルート: 固定（「固定するルート」2）
- 解釈不能な未完了実行の起動時Abort: 完了またはAbortの事実がなく、保存定義を現行コードで解釈できない実行を、起動時に理由付きAbortの事実で `Aborted` へ収束させる。完了事実がなく既に `Running` に戻っている既存実行も同じ経路で扱う。根拠: R-003 / R-004、B-003 / B-004。ルート: 固定（「固定するルート」3）
- 解釈不能な定義を保持する回復経路の削除: Node の `Unresolved` 状態、`recovery_reason`、保存定義の部分解釈、`DefinitionResolution`、解釈不能なNodeへの依存判定を取り除き、定義解釈不能を理由に進行も終了もできない `Running` のWorkflowExecutionを残さない。根拠: R-005、B-003 / B-004。ルート: 固定（「固定するルート」4）

## 固定するルート

1. 実行木の完了を durable workflow fact として記録する。自然完了を読み取り時の再計算結果ではなく事実として残す。関係: R-001 / B-001
2. 完了事実をAbortと同様の終端事実として保存定義より先に判定する。終端状態を後の定義形式や実行コードの変更から独立させる。関係: R-002 / B-002
3. 完了またはAbortの事実がない解釈不能実行を起動時に理由付きAbortへ収束させ、既存の `Running` へ戻った実行も同じ経路で扱う。読み取り時の判定にはしない。関係: R-003 / R-004、B-003 / B-004
4. `Unresolved`、`recovery_reason`、保存定義の部分解釈と `DefinitionResolution`、解釈不能なNodeへの依存判定を削除し、起動時Abortへ一本化する。関係: R-005、B-003 / B-004

上記以外の具体的な実装方法、配置、作業手順は委任する。

## 変えないもの

- 旧形式の保存定義を現行形式へ移行する経路と、旧形式を継続して解釈する互換経路は追加しない
- 完了事実を持たない既存実行について、過去の自然完了を推定せず、完了事実も補わない
- Archiveの記録統合、実行中の実行をArchiveするときのAbort、消えたWorktreeの実行の片付けは変更しない。#1826 が扱うため
- 起動時処理全体とメモリ上のWorkflow状態は整理しない。保存定義を解釈できない未完了実行のAbort以外は #1840 が扱うため
