## B-001: 拒否の記録は次の受理で 1 回だけ解ける

GIVEN 同時実行の枠に入れなかった呼び出しが、失敗の記録に拒否として出ている
WHEN そのあと呼び出しが枠に受理される
THEN 同じキーの拒否の記録は解かれる
AND それ以降、次の拒否が記録されるまでは、受理が続いても失敗の記録は変わらず、失敗の購読へ変更は出ない

## B-002: 包みの定義の所在

同時実行の枠を掛ける包みの定義は `src-tauri/src/common/` にある。common は他のどの層も参照しない。

## B-003: 優先度の分類と枠の大きさの所在

優先度の分類と、枠の大きさ・待ち行列の長さは、包みの設定として Main が包みへ渡す。common は枠を掛ける仕組みだけを持ち、ClientService の method の名前を持たない。

## B-004: 包みの組み立ての場所

包みの組み立ては Main が行う。controller は枠の実体を作らず、組み立て済みの包みを入口の手前に掛ける。

## B-005: 枠の対象外

GIVEN 他の呼び出しで枠が埋まっている
WHEN 接続の確立の呼び出し、送る量の制御のための呼び出し、または購読の stream が届く
THEN それらは枠を取らずに実行される

## B-006: 枠が埋まったときの結果

GIVEN ある優先度の枠の席が埋まっている
WHEN その優先度の呼び出しが届く
THEN その呼び出しは待ち行列に並び、席が空けば受理される
AND 待ち行列が溢れているとき、または待っても席が空かないときは `RESOURCE_EXHAUSTED` で終わる

## B-007: 画面が受け取る失敗の記録

GIVEN 拒否が失敗の記録に出ている
WHEN 利用者が失敗の一覧を見る
THEN その記録は「要対応」として表示されない
AND 一覧の見え方は、この変更の前と変わらない

## B-008: 使われなくなるコードの不在

この変更で使われなくなったコードは残らない。
