# Requirements

## Type

バグ修正 / 改善

## Goal

AgentChat の権限モードを `Ask` / `Edit` / `Full` の 3 段階として扱い、Claude と Codex の実行時権限へ一貫して変換されるようにする。

完了時には、ユーザーが AgentChat で選んだ権限モードがセッション開始時・実行中の切り替え時・保存値や外部入力を経由した場合のいずれでも同じ意味で扱われ、Codex の `Edit` と `Ask` がユーザー承認を求められる権限として反映されている。

## Background

現在の AgentChat では、抽象的な権限モードが `readonly` / `edit` / `full` として扱われている。しかし Claude の `default` 相当は完全な読み取り専用ではなく、必要な操作についてユーザーに確認できる Ask モードとして扱うほうが自然である。

また、Codex で `Edit` を選んだ場合でも実行環境の承認ポリシーが承認なし相当になり、ユーザー確認が必要な操作で確認要求が出ない状態が確認されている。これにより、UI 上の権限選択と実際の実行権限がずれ、安全側に倒したい操作で期待した確認が発生しない。

この変更では、ユーザーに見える権限モデルと各エージェントバックエンドの権限モデルを揃え、AgentChat の権限選択を予測可能で安全なものにする。

## Users / Actors

- AgentChat を使って Claude または Codex セッションを開始・操作するユーザー
- AgentChat のセッションを実行する Agent
- AgentChat の権限モードを保存・復元・送受信する Releash
- デスクトップ UI、リモート UI、ワークフローなど AgentChat の権限モードを指定する呼び出し元

## Scope

- AgentChat の正規の権限モードを `Ask` / `Edit` / `Full` として定義する。
- UI 表示、保存値、外部入力、セッション開始、実行中の切り替えで `Ask` / `Edit` / `Full` が一貫して扱われるようにする。
- Claude 向けには、`Ask` が確認可能な既定権限、`Edit` が編集許可、`Full` が広い権限として扱われるようにする。
- Codex 向けには、`Ask` と `Edit` が必要に応じてユーザー承認を求める権限、`Full` が承認なしで広い権限を許可するモードとして扱われるようにする。
- 旧 `readonly` 値が既存データや既存ワークフローに残っている場合は、互換的に `Ask` として扱い、新規に保存される値としては使用しないようにする。
- デスクトップ UI とリモート UI の権限モード表示を新しい用語に揃える。
- ワークフローや外部入力が AgentChat の権限モードを指定する場合も、新しい権限モデルに揃える。

## Non-goals

- AgentChat 以外の独立した権限管理モデルを新設すること。
- Claude / Codex 以外のエージェントバックエンド向けに新しい権限体系を設計すること。
- OS や Git 操作そのものの権限制御を追加すること。
- ユーザー承認 UI の全面的な再設計。
- AgentChat のモデル選択、バックエンド選択、セッション管理そのものの仕様変更。
- 既存ワークフロー全体の意味を変更すること。ただし権限モード名の移行に必要な範囲は含める。

## Requirements

- 権限モードはユーザー向け・保存値・外部入力のいずれでも `Ask` / `Edit` / `Full` の 3 種類として説明できること。
- `Ask` は、基本的に安全側の権限で開始し、追加の操作が必要な場合はユーザーに確認できるモードであること。
- `Edit` は、ワークスペース内の編集を許可し、それを超える操作や確認が必要な操作ではユーザーに確認できるモードであること。
- `Full` は、広い操作権限を承認なしで許可するモードであること。
- Claude を使う場合、`Ask` / `Edit` / `Full` が Claude 側の対応する権限意味へ変換されること。
- Codex を使う場合、`Ask` は読み取り中心かつ承認要求可能な実行権限として扱われること。
- Codex を使う場合、`Edit` はワークスペース内編集を許可しつつ承認要求可能な実行権限として扱われること。
- Codex を使う場合、`Full` は広い実行権限かつ承認なしの権限として扱われること。
- AgentChat で `Ask` または `Edit` を選択してセッションを開始した場合、承認が必要な操作でユーザー確認が表示されること。
- AgentChat で実行中に権限モードを切り替えた場合、切り替え後の実行権限が新しい権限モデルに従うこと。
- 旧 `readonly` は新規の保存値・送信値・UI 表示として使われないこと。
- 既存データや既存ワークフローに旧 `readonly` が含まれる場合は、互換的に `Ask` として扱うこと。
- デスクトップ UI、リモート UI、ワークフロー入力、セッション保存・復元の間で同じ権限モードが同じ意味を持つこと。
- 不正な権限モード値が指定された場合、既定値への黙示的なフォールバックで権限が広がらないこと。

## Constraints

- 権限モードの名称と意味は、ユーザーが UI 上で理解できる表現と実際の実行権限がずれないこと。
- 安全側のモードでユーザー承認を必要とする操作が、承認なしで実行可能にならないこと。
- 既存ユーザーの保存済みセッションやワークフローを扱う際に、意図せず権限が広がらないこと。
- デスクトップとリモートで同じ権限モード名が異なる意味を持たないこと。
- 新しい権限モデルへの移行後も、ユーザーが選べる権限段階は 3 段階に留めること。

## Success Criteria

- AgentChat の権限モードが `Ask` / `Edit` / `Full` として表示・保存・復元・指定できる。
- Claude セッションで各権限モードが期待される権限意味として反映される。
- Codex セッションで `Ask` と `Edit` が承認要求可能な権限として反映される。
- Codex セッションで `Full` が承認なしの広い権限として反映される。
- `Edit` を選択した Codex セッションで、承認が必要な操作に対して確認要求が発生する。
- `Ask` を選択した Codex セッションで、承認が必要な操作に対して確認要求が発生する。
- 旧 `readonly` の扱いが明示され、新規の正規値としては使われない。
- デスクトップ UI、リモート UI、ワークフロー入力、セッション保存・復元で権限モードの意味が一致する。
- 関連する検証で、権限モードの変換・保存・復元・不正値処理が確認できる。

## Open Questions

- UI 上の表記は英語の `Ask` / `Edit` / `Full` に統一するか、日本語表示を併記するか。
- 旧 `readonly` を受け付ける互換期間を設ける場合、その終了条件をどう定義するか。
