## B-001: domain の失敗の語彙

domain が表す失敗は業務の意味があるものだけである。転送の語彙（gRPC のステータスコード、HTTP status）と 1 対 1 に対応する分類は domain に無い。

## B-002: trait の失敗の形

trait の失敗は、業務の結果と、中身を見ない技術的な失敗の変種 1 つで表される。技術的な失敗が一時的か、やり直してよいかは、domain の判断の根拠に使われていない。

## B-003: 転送のステータスコードを決める場所

Usecase が出した失敗から転送のステータスコードを決めるのは presenter の 1 か所だけである。業務の失敗と技術的な失敗は区別して対応付けられる。presenter の外では転送の失敗が組み立てられていない。

## B-004: 版の競合で業務の手順をやり直す

GIVEN 業務の手順の途中で集約の版の競合が起きる
WHEN その手順を実行している Usecase がやり直すかを決める
THEN 判断の根拠は、版が競合したという業務の失敗である

## B-005: 一時的な技術的な失敗をやり直す

GIVEN 外部世界への呼び出しが技術的な失敗をする
WHEN その呼び出しをやり直すかが決まる
THEN 判断の根拠は、その技術的な失敗が持つ一時的かどうかの性質である

## B-006: Node の失敗にしない判定

GIVEN Node の実行中に集約の版の競合が起きる
WHEN その失敗が「やり直しで直る失敗は Node の失敗にしない」の判定を通る
THEN その Node は失敗として確定しない
AND この結果は、その判定を通るどの経路でも同じである

## B-007: 既存のステータスコード

GIVEN 画面または CLI が失敗する呼び出しを行う
WHEN その呼び出しが失敗する
THEN 受け取る転送のステータスコードは、この変更の前と同じである

## B-008: 期限切れの結果

GIVEN 外部世界への呼び出しに自前の期限が掛かっている
WHEN その期限が切れ、その失敗が Connect を通って返る
THEN 受け取る Connect のステータスコードは `DEADLINE_EXCEEDED` である
AND その失敗が HTTP local API を通って返る場合、受け取る HTTP status は 500 である

## B-009: AppError の serialize 表現

GIVEN フロントが Tauri のコマンドを呼ぶ
WHEN そのコマンドが失敗を返す
THEN 通常の失敗はメッセージのプレーン文字列として観測できる
AND `code` を持つ失敗は `code` と `message` の object として観測できる

## B-010: Tauri のシェルの生存確認

GIVEN Tauri のシェルが daemon の生存確認を繰り返している
WHEN 生存確認が、同時に処理できる呼び出しの枠が埋まったことにより失敗する
THEN シェルは daemon が落ちたと見なさず、生存確認を続ける

## B-011: 要対応にならない失敗

GIVEN 対象が、一時的な技術的な失敗、取り消しによる技術的な失敗、または集約の版の競合で失敗する
WHEN 利用者がその対象の表示と失敗の記録を見る
THEN その対象は「要対応」として表示されない

## B-012: 使われなくなるコードの不在

この変更で使われなくなったコードは残らない。

## B-013: 技術的な失敗が運ぶ値

GIVEN Usecase が技術的な失敗を出す
WHEN presenter がそれを転送のステータスコードへ対応付ける
THEN 一時的・期限切れ・取り消し・それ以外の区別が、その失敗だけから導ける
AND store の失敗では元の失敗の値もその失敗から導け、presenter はより細かいステータスコードを選ぶときだけそれを見る

## B-014: 要対応になる失敗

GIVEN 対象が、期限切れによる技術的な失敗、それ以外の技術的な失敗、または版の競合以外の業務の失敗で失敗する
WHEN 利用者がその対象の表示と失敗の記録を見る
THEN その対象は「要対応」として表示される

## B-015: 失敗の記録の分類

GIVEN 対象が失敗し、失敗の記録に残る
WHEN 利用者がその記録を見る
THEN 分類として、業務の失敗（集約の版の競合、それ以外）と技術的な失敗の性質（一時的、期限切れ、取り消し、それ以外）の 6 つに対応する文字列のいずれかが観測できる
AND 同じ対象・同じ操作で分類が同じ失敗は、1 件の記録にまとまって観測できる

## B-016: Node に残る失敗の理由

GIVEN ある対象の失敗が解消され、その後に別の失敗が起きる
WHEN 利用者がその対象の Node に表示される失敗の理由を見る
THEN 観測できるのは、今有効な失敗の記録の message である
AND 解消済みの記録の message は観測できない
