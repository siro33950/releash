# Behavior

対象 Issue: #1190
対象 requirements: `docs/specs/feat-issues-1190/requirements.md`

本書は requirements の要求を、実装詳細（永続化経路・SDK resume 機構・識別子の受け渡し方法等）を含まない、外部から観測可能な振る舞いとして Gherkin で定義する。

## 仮定

- 「文脈依存の発話」とは、直前までの会話で確立した情報（直前に決めた前提・直前に名付けた対象・直前の指示の続き等）を参照しないと正しく応答できない発話を指す。検証時は、復帰前のやり取りを参照しなければ答えられない質問を用いる。
- 「Agent が復帰前の会話コンテキストを踏まえて応答する」とは、復帰後の最初の文脈依存の発話に対して、Agent の応答が復帰前のやり取りに依存した内容になっている状態を指す（外部観測）。応答の正確さや品質そのものは対象としない。
- 「引き継ぎ済み」とは、復帰 Session について UI 上で会話履歴が引き継がれたように見える状態を指す。本書では、この見え方と Agent 側の実際の記憶状態が一致しているかどうかを振る舞いとして扱う。
- 全 backend で会話コンテキストの引き継ぎを保証する（合意済み・案 A）。resume が技術的に成立する場合にそれを用いるか、Releash が保持する `messages` の再注入を用いるかは手段の違いであり、観測される振る舞い（復帰前コンテキストを踏まえて応答する）は手段に依存しない。本書では手段を区別せず「引き継ぐ」として記述する。
- 「引き継ぎが成立しない」とは、復帰前コンテキストを Agent が参照できる状態にできなかったことを指す。案 A により通常フローでは成立を保証するため、これは再注入を含むすべての引き継ぎ手段が機能しなかった例外ケースとして扱う。
- トークン上限等による自然な切り詰めは引き継ぎ失敗に含めない。

## Feature: 復帰 Session の会話コンテキスト引き継ぎ

  復帰した Session で会話を続けるユーザーが、復帰前のやり取りを Agent が記憶した状態で続行できる。
  UI 上の「引き継ぎ済み」の見え方と、Agent の実際の記憶状態が一致する。

  Background:
    Given 数ターン会話して文脈が確立した Session が存在する
    And その Session が永続化されている

  Rule: 復帰した Session で発話すると、Agent は復帰前の会話コンテキストを踏まえて応答する

    Scenario: 再起動後に Session を開いて続行する
      Given Releash を再起動した
      When その Session を一覧から開いて文脈依存の発話をする
      Then Agent は復帰前のやり取りを踏まえて応答する

    Scenario: Closed セッションを履歴から復帰して続行する
      Given その Session が Closed である
      When その Session を「履歴から復帰」して文脈依存の発話をする
      Then Agent は復帰前のやり取りを踏まえて応答する

    Scenario Outline: backend によらず復帰後にコンテキストを引き継ぐ
      Given その Session の backend が <backend> である
      When その Session を復帰して文脈依存の発話をする
      Then Agent は復帰前のやり取りを踏まえて応答する

      Examples:
        | backend |
        | Claude  |
        | Codex   |

  Rule: UI 上「引き継ぎ済み」に見える復帰 Session は、Agent 側のコンテキストも引き継いだ状態である

    Scenario: 表示上の引き継ぎと Agent の記憶状態が一致する
      When その Session を復帰する
      Then UI 上「引き継ぎ済み」に見える
      And 復帰後の文脈依存の発話に対して Agent は復帰前のやり取りを踏まえて応答する

  Rule: 引き継ぎが成立しなかった場合は「引き継ぎ済み」と誤認させない

    Scenario: コンテキスト引き継ぎが成立しなかった復帰 Session
      Given その Session の復帰でコンテキストの引き継ぎが成立しなかった
      When その Session を表示する
      Then UI 上「引き継ぎ済み」と誤認させない
      And 引き継ぎが成立しなかったことを利用者またはシステムが識別できる

    Scenario: 引き継ぎが成立しなかった Session で発話する
      Given その Session の復帰でコンテキストの引き継ぎが成立しなかった
      And 引き継ぎが成立しなかったことが利用者に示されている
      When 発話する
      Then 発話の続行が許可される
      And Agent は引き継ぐべき過去コンテキストなしで応答する

  Rule: 復帰経路の変更が、引き継ぎを伴わない通常の挙動を壊さない

    Scenario: 新規 Session を開始して発話する
      Given 復帰元のない新規 Session である
      When 発話する
      Then Agent は引き継ぐべき過去コンテキストなしで通常どおり応答する

    Scenario: 同一起動中にターンを継続する
      Given 復帰を伴わず起動中の Session で会話を継続している
      When 続けて発話する
      Then Agent は直前までのコンテキストを保ったまま通常どおり応答する

  Rule: 既存の永続化済み Session を開いても、コンテキストや履歴を破壊しない

    Scenario: 旧フォーマットで保存された Session を開く
      Given 旧フォーマットで永続化された Session である
      When その Session を開く
      Then 表示用のメッセージ履歴が破壊されない
      And その Session のコンテキスト状態が破壊されない
