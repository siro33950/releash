- 見た目の参考は、ISSUE #2127 の本文に貼られた mock 2 枚（「ファイルタブの Thread」「ファイルタブで Thread を作る」）である。mock のファイル、コード、Comment の名前は例である。
- 調査の時点は main `373fb61b` である。
- ISSUE #2127 が見せ方の基準にしている Thread 面の作り替えは、ISSUE #2126 が扱う。調査の時点で #2126 は未着手であり、Thread 面は作り替える前の見せ方のままである。この文書は、ファイルタブに出すものを Thread 面を参照せずに定める。

# Outcome

対象者は、Swift.app のファイルタブでコードと差分を読み、行に付けた Thread で agent とやり取りする開発者である。

今のファイルタブは、行の下の Thread に、最初の Comment の書き手の名前と、Comment の本文だけを並べる。
開発者は、2 件目以降の Comment を誰が書いたか、各 Comment がいつ書かれたか、agent がどの model で書いたかを、ファイルタブでは読めない。
本文は Markdown の記号が付いたまま出る。
Thread を作るには、行を選んだあと、シートを開いて書く。

変更後は、行の下のカードに、すべての Comment が、書き手のアイコン、名前、書いた時刻の相対表示、Markdown として整形した本文とともに出る。
解決済みの Thread は、解決にした人と時刻の 1 行にたたまれ、開いて読める。
開発者は、シートを開かずに、選んだ行の下のカードで Thread を作れる。
Comment の本文の HTML、画像、リンクは、Thread 面とファイルタブで同じ扱いになる。

# Current Behavior

調査は main `373fb61b` のコードを読み、CI の実行結果を確かめて行った。
アプリの画面を見ることはしていない。

## 行の下の Thread

- File 表示と Diff 表示のどちらでも、Thread は、Thread が付いた範囲の最後の行の下に出る（`clients/macos/FileViewer/bridge.js:125-131`）。
- 範囲の行には左端に印が付く。未解決の Thread の範囲の行には、薄い色も付く（`bridge.js:56-65`）。
- Thread の見出しには、最初の Comment の書き手の名前だけが出る。解決済みの Thread は、見出しが「名前（解決済み）」になり、畳んで出る。見出しを押すたびに開閉する（`bridge.js:68-75`）。
- Comment は本文だけが古い順に並ぶ。2 件目以降の Comment の書き手、各 Comment を書いた時刻、agent の model は出ない（`bridge.js:76-80`）。
- 本文は文字のまま出る。Markdown の記号、HTML のタグ、画像の記法、リンクの記法は、書かれた文字がそのまま見える（`bridge.js:76-79`）。
- 未解決の Thread には、複数行の入力欄、「返信」ボタン、「解決」ボタンが出る。返信は「返信」ボタンで送る。入力欄で Return を押すと改行する（`bridge.js:81-93`）。
- 解決済みの Thread には、入力欄もボタンも出ない（`bridge.js:81`）。解決にした人と、解決にした時刻も出ない。

## Thread を作る操作

- 行を選ぶと、帯に「Thread作成」が出る（`FileTabPane.swift:82-85`）。
- 「Thread作成」を押すと、シートが開く。シートには、見出し「Thread作成」、入力欄、「キャンセル」、「作成」が出る。入力欄が空白だけのあいだ、「作成」は押せない（`FileTabPane.swift:65-75`）。
- 「作成」を押すと、選んだ範囲に Thread ができ、シートが閉じる（`FileTabPane.swift:253-267`）。

## Thread 面の Comment の本文

- Thread 面は、Comment の本文を Markdown として整形して出す（`clients/macos/Sources/ThreadPanelView.swift:229-231`、`:239`）。
- Thread 面は、本文に URL で書かれた画像を出さない（`ThreadPanelView.swift:72`、`:181-187`）。
- Thread 面は、本文に書かれた HTML や script を動かさない。
- Thread 面で本文のリンクを押すと、リンク先が既定のブラウザで開く。
- 調査の時点の Thread 面は、最初の Comment と、最後の Comment の書き手と日時を出し、2 件目以降の Comment は「Commentを表示」を開くまで出さない。書き手のアイコン、相対表示の時刻、agent の model は出さない（`ThreadPanelView.swift:214-243`）。

## 再現手順

アプリの画面での再現はしていない。
代わりに、main への push の CI（run `43322472303`、commit `50484080`）で、ファイルタブの行の下の Thread を確かめる単体テスト（`clients/macos/FileViewer/bridge.test.js:104-130`）が実行され、成功したことを確かめた。
commit `50484080` から調査の時点までに、ファイルタブの Thread の表示と操作のコードは変わっていない。

このテストは、次の手順でファイルタブの行の下の表示を作り、出力を確かめる。

1. 書き手が `human`、本文が `selected deleted line` の Comment を 1 件持つ未解決の Thread を、Diff 表示の行に出す。
2. 入力欄に `reply body` と書き、「返信」を押す。
3. 返信が Comment として加わった Thread を出し直す。
4. 「解決」を押す。
5. 解決済みになった Thread を出し直す。

実際の出力は次のとおりである。

| 手順 | 出力 |
| --- | --- |
| 1 | Thread は開いて出る。見出しは `human` で、その下に本文 `selected deleted line` が出る |
| 2 | 本文 `reply body` の返信が送られる |
| 3 | 2 件目の本文として `reply body` が出る。見出しは `human` のままで、`reply body` の書き手と書いた時刻は出ない |
| 4 | その Thread の解決が送られる |
| 5 | Thread は畳んで出る。見出しは `human（解決済み）` である。出るのは見出しと本文だけで、入力欄、ボタン、解決にした人、解決にした時刻は出ない |

Thread を作るシートと、Thread 面の Comment の本文は、この実行では確かめていない。
この二つは、コードを読んだ結果である。

# Scope / Non-goals

変更するもの:

- ファイルタブの File 表示と Diff 表示で、行の下に出る未解決の Thread と解決済みの Thread の見せ方。
- ファイルタブで返信を送る操作。
- ファイルタブで Thread を作る操作。シートをやめ、選んだ行の下のカードで書く。
- ファイルタブでの Comment の本文の表示。Markdown として整形する。
- Thread 面とファイルタブでの、Comment の本文の HTML、画像、リンクの扱い。Thread 面の画像の扱いも変える。

Non-goals:

- Thread 面のカードの並びと見せ方の作り替え。ISSUE #2126 が扱う。

# Requirements

- R-001: File 表示と Diff 表示のどちらでも、未解決の Thread は、Thread が付いた範囲の最後の行の下に、カードで出る。カードには、その Thread のすべての Comment が古い順に並ぶ。
- R-002: カードの各 Comment には、書き手のアイコン、書き手の名前、書いた時刻の相対表示、本文が出る。書き手が人のとき、アイコンは名前の頭文字である。書き手が agent のとき、アイコンは agent を表す絵であり、名前の右にその agent の model が出る。model が記録されていない Comment では、model は出ない。
- R-003: カードの Comment の本文は、Markdown として整形されて出る。見出し、箇条書き、コード、強調が整形される。
- R-004: カードには、Thread が付いたファイルの path、行番号、差分は出ない。
- R-005: 未解決の Thread のカードの下端に、「返信を書く…」と案内する入力欄と、「解決にする」ボタンが出る。
- R-006: 開発者が入力欄に文を書いて ⌘Return を押すと、その文が返信として送られ、その Thread の最後の Comment としてカードに出る。入力欄は空に戻る。Return だけを押すと、入力欄の中で改行し、返信は送られない。
- R-007: 開発者が「解決にする」を押すと、その Thread は解決済みになり、カードは R-008 の 1 行に替わる。
- R-008: File 表示と Diff 表示のどちらでも、解決済みの Thread は、Thread が付いた範囲の最後の行の下に、1 行で出る。行には、解決にした人の名前、解決にした時刻の相対表示、「表示」ボタンが出る。文面は「siro33950 が解決にしました · 1 時間前」の形である。
- R-009: 開発者が「表示」を押すと、1 行の下に、その Thread のすべての Comment が R-002、R-003 と同じ形で出て、「表示」は「隠す」に替わる。「隠す」を押すと、Comment は消え、「隠す」は「表示」に替わり、1 行だけに戻る。解決済みの Thread には、返信の入力欄と「解決にする」ボタンは出ない。
- R-010: 開発者が行を選んで帯の「Thread作成」を押すと、シートは開かず、選んだ範囲の最後の行の下に、Thread を作るカードが出る。このカードには、「コメントを書く…（Markdown）」と案内する入力欄、「キャンセル」ボタン、「Thread を作る」ボタンが出る。カードが出た時点で、開発者は入力欄を押さずに文字を打てる。
- R-011: 開発者が入力欄に文を書いて「Thread を作る」を押すと、選んだ範囲に、その文を最初の Comment とする Thread ができる。Thread を作るカードは消え、できた Thread が R-001 のカードで出る。
- R-012: 開発者が「キャンセル」を押すと、Thread はできず、Thread を作るカードは消える。
- R-013: Comment の本文に URL で書かれた画像は、ファイルタブのカードと Thread 面のどちらでも、本文の中に画像として出る。
- R-014: 開発者が Comment の本文のリンクを押すと、ファイルタブのカードと Thread 面のどちらでも、リンク先が既定のブラウザで開く。
- R-015: Comment の本文に HTML や script が書かれていても、ファイルタブのカードと Thread 面のどちらでも、それらは動かない。本文が表示されただけで、返信、解決、Thread の作成が行われることはない。
