## Behavior

```gherkin
Feature: ワークフロー構成の4ワークフロー再編
  Rule: Spec は対話によって構築される
    Scenario: 対話を通じて Spec が完成する
      Given 開発者が新しい Spec を作成しようとしている
      When 開発者がエージェントとの対話を進める
      Then Spec が対話の結果として構築される
      And レビューループによる磨き込み工程は介在しない

  Rule: 実装は軽量レビューで Spec 充足と規約適合を保証する
    Scenario: Spec を元に実装を生成する
      Given Spec が用意されている
      When エージェントが実装ワークフローを実行する
      Then エージェントが Spec を元に実装を行う

    Scenario: 指摘を反映しながら最大2周のレビューで実装を仕上げる
      Given エージェントが Spec を元に実装を行った
      When レビューで指摘が出る
      Then エージェントが人間の確認を挟まず指摘を反映して実装を修正する
      And 修正後の実装が再度レビューされる
      And レビューと修正の繰り返しは最大2周で打ち切られる

    Scenario: レビューで指摘が出なければ実装を完了する
      Given エージェントが Spec を元に実装を行った
      When 実装が Spec と実装規約の両方に適合しているかレビューされ、指摘が出ない
      Then ワークフローは実装を完了として終了する

  Rule: フルレビューは全観点を高精度に検証し人間が判断する
    Scenario: 全観点を複数の高性能モデルでレビューする
      Given 実装が完了している
      When 開発者がフルレビューを実行する
      Then acceptance / structure / quality / test / security / architecture の全観点が複数の高性能モデルでレビューされる

    Scenario: レビュー結果の妥当性をモデルごとに検証する
      Given 全観点のレビュー結果がある
      When 各指摘が妥当かどうか確かめられる
      Then モデルごとに独立して妥当性が判定される

    Scenario: 検証されたレビュー結果を人間が判断する
      Given 妥当性が判定されたレビュー結果がある
      When 開発者がレビュー結果を逐次確認する
      Then 開発者が各指摘について採用・却下・修正方針を決める

  Rule: フルレビュー後の修正は未対応の指摘を元に承認付きで行う
    Scenario: 未対応の指摘を元に承認を挟んで修正する
      Given フルレビューで未対応の指摘が残っている
      When エージェントが修正ワークフローを実行する
      Then エージェントが未対応の指摘を元に修正を行う
      And 修正は開発者の承認を経て進む

    Scenario: 各指摘は解決済みか未対応のいずれかに落ち着く
      Given フルレビュー後の修正を進めている
      When 各指摘の扱いを決める
      Then 対応した指摘と対応を見送った指摘は解決済みになる
      And 後で対応する指摘や対応中の指摘は未対応のまま残る

  Rule: 利用可能なワークフローは新4構成のみ
    Scenario: 従来のワークフローは利用できず新4ワークフローのみ存在する
      Given ワークフロー構成が再編された
      When 利用可能なワークフローを確認する
      Then Spec作成・実装・フルレビュー・フルレビュー後修正の4ワークフローのみが利用できる
      And 従来のワークフローは利用できない

    Scenario: どのワークフローからも参照されない資産は残さない
      Given ワークフロー構成が再編された
      When 各ワークフローが参照する資産を確認する
      Then 新4ワークフローのいずれからも参照されない資産は残っていない
```
